# S31b6b3c1 — 7-Zip output identita a závislost úklidu

Parent5c8c8d72b3ff6796e0fe9ffd4515a4a57e42ec73; donor
47661e92d4b3cbe5bb593ae3d75a3f1f698ef413. Před diagnostikou zapsaná kvalifikační
podetapa. Předchozí b3a doložila konverzní nesoulad se storage facades; nyní
je důkaz rozšířen na skutečné vendor typy, stream a filesystem I/O. Produkční
src/tools i původní assertions zůstávají beze změny. Jde o důkaz chyb a přesný
závazek opravy, nikoli o uzavření S31b6b3c nebo správné rozbalování celého archivu.

## Konkrétní hranice

CArchiveItemInfo::NameInArchive je CSysString; projekt používá byte host cesty.
GetStream nejprve neomezeně kopíruje TargetDir do TargetFileName[SAL_MAX_PATH],
teprve potom volá SalPathAppend. Nový bounds check proto musí předcházet kopii,
nikoli pouze sledovat výsledek append. Nesplněný limit nesmí otevřít/create output.
ProcessedFileInfo.FileName = GetUnicodeString(TargetFileName) používá Windows
CP_ACP; následný stream Open znovu roundtripuje GetUnicodeString(GetAnsiString(...)).
Přitom metadata/Name a součty/výběr CItemData::Idx musí zůstat u původního ownera.

Před stream Open se přes WM_7ZIP_CREATEFILE a SalamanderSafeFile->SafeFileCreate
provádí existující overwrite/skip/cancel kontrakt a vzniká prázdný cílový soubor.
Tyto dialogy a výsledky se nesmějí obejít přímým CreateFile. Následující
CheckAndCreateDirectory zkrátí TargetFileName na parent nulovým znakem;
GetFileName() vrací tento buffer, nelze ho později bez rozmyslu znovu použít jako
identitu plného outputu. Directory-only větev CheckAndCreateDirectory také musí
hlásit selhání a používat stejnou správnou cestu; její návratová hodnota je nyní
ignorovaná. Host SDK forwarding je v zip.cpp, skutečná implementace v salamdr3.cpp.

Cleanup při přerušení, OnDataError Cancel/Delete/Keep a SetOperationResult
používají ProcessedFileInfo.FileName. SafeDeleteFile již v 7zip.cpp konvertuje
svůj char vstup UTF8-first a volá DeleteFileW s extended prefixem. Jeho volající
v extract.cpp ale předá GetAnsiString(wide), čímž po správném wide převodu může
ztratit ne-ACP znaky. Attributes větve používají ANSI SetFileAttributes.
Pouhá náhrada dvou řádků streamu tedy neřeší úplný lifecycle. Cleanup musí smazat
jen odpovídající nehotový output po zavření handle, zachovat Retry/Skip/Cancel
chování a nesmí plošně potlačit chyby ani měnit readonly oprávnění Windows.

## Reálný nativní důkaz

Externí Stream-Probe.py překládá původní vendor MyString/MyVector/IntToString/
StringConvert, FileStreams, Windows FileIO/FileName/FileDir/FileFind/PropVariant/
TimeUtils. Žádné AString/UString/stream storage facades. GetSalamanderUnicodeString
+ GetSalamanderLongPath a SafeDeleteFile jsou extrahovány z aktuálního zdroje;
jen GeneralFacade nahrazuje error dialog návratem Cancel a jeho počítadlem.
UI se nespouští. g_IsNT=true odpovídá diagnostice běžící na NT; INITGUID a ole2.h
poskytují COM deklarace/linkování, nemění vendor konverze nebo code page.

Šest vlastních shapes: ASCII; Unicode leaf v ASCII parentu; Unicode parent;
více Unicode komponent; UTF8-byte-long při UTF16<260; skutečný UTF16-long parent.
Root je nový owned-fixtures uvnitř unikátního dočasného adresáře a před I/O se
ověří jeho neexistence. Legacy výraz je předán skutečnému COutFileStream::Open
s OPEN_ALWAYS, stejným disposition jako production GetStream. Čtení používá
CreateFileW a kontroluje přesné bytes. Samostatný sentinel zůstává beze změny.
Výsledky v Debug i Release /W4 /WX, skutečné ACP1250:99 checks/config;
ASCII soubor správný, dvě Unicode větve vytvoří mojibake leaf, další tři nemají
existující poškozený parent a otevření selže. Explicitní UTF8-first wide+extended
varianta zapíše správný soubor ve všech pěti Unicode shapes, nastaví timestamp.

Nad správným wide outputem současný ANSI attribute výraz selže, wide alternativa
nastaví HIDDEN na přesné cestě. SafeDeleteFile(GetAnsiString(exactWide)) ve všech
pěti Unicode shapes narazí na chybu a error facade vrátí Cancel; přesná data
zůstanou. Naopak při původní chybné ACP wide identitě roundtrip vrátí původní UTF8
bytes, takže stávající SafeDeleteFile smaže správně pojmenovaný testovací output,
a samostatný špatně pojmenovaný legacy soubor ponechá. To je konkrétní nesoulad
identity zápisu/úklidu nad vlastní fixture, ne hypotéza o možném výsledku GUI.
Wrong outputs následně odstraní explicitní vlastní-fixture Win32 cleanup;
adresáře se odstraňují od známých listů pouze do ověřeného owned rootu.

První sestavení probe chybělo ole2.h a vendor PropVariant/TimeUtils/GUID deps;
compile/link selhal před runtime. První obecný std::filesystem remove_all úklid
nezvládl dlouhé empty directories, záznam chyby je uchovaný. Opraven explicitní
DeleteFileW/RemoveDirectoryW úklid přes extended cesty; zbylé dva unikátní testovací
temp roots byly ověřeny a odstraněny přes extended-prefix Python. Finální D/R
průchody včetně úklidu PASS, neúspěšné přípravy se za PASS nepočítají.

Tento probe nevolá 7za.dll, CRetryableOutFileStream::Write error UI, skutečný host
SafeFileCreate/CheckAndCreateDirectory, archiver enumeration ani CRC/decompression.
Nemá důkaz overwrite/skip/GUI/cancel celé operace; nehodnotí bezpečnost neznámých
archivů a nepoužívá škodlivé položky. Je diagnostikou stávajících I/O gaps.
Dosavadní produkční testy se nenahrazují očekáváním chyb. Při opravě vzniknou
permanentní testy správného výsledku a negativní kontrola starého chování.
