## Skutečný průchod

CM_UNPACK v mainwnd3 volí ordinary/nonactive nebo detached operation target a
volá Unpack. Aktivní Branch panel navíc odmítá centrální BranchReadOnlyCommandAllowed
(CM_UNPACK v seznamu není). Unpack má vlastní source i target Branch guard.
Alt+F9 tedy není F5 archive-panel UnpackZIPArchive/PackUncompress. F5 qualification
ze S31b6b3c3 ani plugin output guard není důkaz celé whole-archive operace.

| Hranice | Aktuální důkaz / mezera |
| --- | --- |
| C01 source context | PrepareUnpackArchiveSource používá GetItemFullPathW, exact UTF8 roundtrip a byte kapacitu SAL_MAX_PATH. Owned archiveSource vzniká před modalem, po něm už není file->. sourceDirectory je však stále GetPathW panelu, relativní výstup SalGetFullName používá tento root. Pro budoucí Branch source musí odpovídat skutečnému parentu vybraného archivu, bez root+basename rekonstrukce. Owned string nezajišťuje životnost this/panelu: po modalu jsou Is/GetPath/NextFocus a další callbacky. |
| C02 target context | Default se převádí lossless z target GetPathW, ale chybí CFilesActionDiskTarget a ověření po dialogu/před vytvářením i po InitDLL. Snapshot F5 se do této pipeline zatím nepředává. Uložený text není záruka identity tabu. |
| C03 backend context | ExecuteUnpacker bere PreferedUnpacker a jeho Type. External větev jde do PackUniversalUncompress; plugin větev vyžaduje SupportCustomUnpack a volá UnpackWholeArchive. Není zde private listing k převzetí owner policy F5. Concrete wrapper po InitDLL ihned konstruuje operation context a volá SDK callback, bez kontroly targetu/kind/config. Dispatcher i wrapper jsou přesně donorové. |
| C04 whole-archive items | 7-Zip UnpackWholeArchive vytváří listing a volá CalcSize/GatherItems, teprve pak Decompress. archivePath[MAX_PATH_LEN] má MAX_PATH_LEN=SAL_MAX_PATH, ale GatherItems dvakrát předává SalPathAppend kapacitu MAX_PATH. U file append failure přeskočí file, u directory failure celý podstrom a nakonec vrátí OPER_OK. C2 GetStream guard tento dřívější výběr neopravuje. GatherItems je přesně donorový; nejde o prokázaný overflow, ale o staticky doložené tiché vynechání. |
| C05 volume deletion | Controller po úspěchu iteruje CDynamicString archiveVolumes a volá ClearReadOnlyAttr(name), DeleteFile(name), retry/skip/cancel dialog. ZIP vrací deduplikované volumes;7-Zip přidává vstupní fileName před otevřením a má FIXME pro více volumes. UTF8 source capture nedokazuje byte deletion identity ani správnost success/skip/partial/cancel rozhodnutí. |

ZIP whole-archive vytváří vlastní CZipUnpack a má explicitní ErrorID/UserBreak
větve před předáním archiveVolumes. 7-Zip používá vlastní listing/client/password
a CalcSize/GatherItems; jeho Decompress output oprava z c2 je společná, ale tento
nový pre-engine průchod nebyl tehdy proveden. Rozdíly je nutné ověřit samostatně.
Existující long source I/O helper není důkaz navigace do takového panelu; odložený
ChangeDir pád ani jeho WIP se neopravuje/neschovává do tohoto auditu.

## Nejmenší navazující kroky a podmínky

1. **S31b6c2 — exact source-parent context bez admission.** Odvodit parent pro
   relativní target a fallback z owned exact archive identity, zachovat oddělený
   basename/display/mask. Před změnou zmapovat existující wide cut/root helpers,
   znovu použít je místo nové generické vrstvy. Native actual helpers D/R:
   ASCII, Unicode basename/parent/multiple, UTF8-byte-long i UTF16-long, stejná
   basename v různých parents, last-byte/bad conversion; potvrdit nezměněný
   ordinary default/subdir/relative target a Cancel v GUI D/R. Branch guard zůstane.
2. **S31b6c3 — whole-archive7Zip collection.** Opravit konkrétní C04 před rozšířením
   admission: actual GatherItems s explicitní podporovanou kapacitou/owned storage,
   při nepodporované položce explicitní failure, žádné tiché vynechání a žádné
   přímé I/O nezvalidovaného jména. Nativně celé file/directory/mask/recursive
   položky, metadata/index vazby a failure propagace. Plugin/deps/host D/R,
   ordinary Alt+F9 GUI s Unicode/long internal entries a exact tree/sentinels.
3. **S31b6c4 — source/target/backend lifecycle před admission.** Zmapovat a převzít
   existující live-registry/owned target principy; source string sám nestačí pro
   operation context a následné refresh/focus. Přesné validace po modal/callback
   a InitDLL před I/O, konfigurace/backend nesmí změnit zvolenou kvalifikaci.
   Interní concrete overload/snapshot může zachovat SDK ABI a ordinary callers;
   žádná nová veřejná capability. Native close/switch/detach/generation/kind/
   config/backend failure, GUI modal target changes D/R a nulové vedlejší výstupy.
4. **S31b6c5 — Branch source -> ordinary disk target.** Teprve po c2–c4 doplnit
   guarded command/enabler/controller source admission pro skutečně ověřené
   bundled whole-archive backendy; výchozí delArchiveWhenDone zatím nesmí rozšířit
   neověřené delete chování. GUI D/R ZIP a7z, duplicate-basename source parents,
   preference/subdir/manual-relative target, Cancel/error/skip, přesný obsah a
   nedotčené zdroje/sentinels. Ostatní backendy až po samostatné kvalifikaci.
5. **S31b6c6 — Branch target direct Unpack.** Samostatná root-directory default
   klasifikace a target admission na ověřeném lifecycle; nikdy focused subdir
   jako nečekaný root. Native stale/current a post-init; actual D/R default,
   manual refusal/explicit supported decision, missing root, long Unicode target.
6. **S31b6c7 — delArchiveWhenDone/volumes.** Než bude tato volba pro nové Branch
   případy povolena, exact-wide volume identities a jasné return/success/partial/
   skip/cancel pravidlo. Zachovat readonly a Windows security/confirmation/retry
   chování, žádný obecný delete fallback. ZIP multi-volume dedup a7-Zip skutečný
   single-volume kontrakt vyžadují vlastní native/plugin/host/GUI D/R s own data,
   Cancel beze změny a content proof před případným potvrzeným mazáním.

Je-li některý krok větší, nejprve zapsat jeho nejmenší pevně provázané podetapy
a přesné testy. Tento plán neoznačuje jejich implementaci za hotovou ani trvalé
odmítnutí za náhradu požadované podpory. Pack Branch target a F5 source lifetime
mají nadále vlastní otevřené hranice. Celá S31/G04/G05 zůstává OPEN, nikoli S32.
