## Evidence and actual behavior

The bundled wrapper hands off one input name for deletion. The production open
callback inherits IArchiveOpenVolumeCallback but MY_UNKNOWN_IMP1 exposes only
ICryptoGetTextPassword through QueryInterface. Actual built Debug and Release
7za.dll both return E_NOINTERFACE0x80004002 for that volume callback. Existing
GetStream/GetProperty no-op bodies do not implement volume discovery. No new
interface exposure, stub implementation or generic alternate-volume access was
added by this audit; multi-volume support cannot be inferred from inheritance.

A bounded C++ /W4 /WX audit loads the existing b2-qualified actual7za.dll in each
configuration. Known ZIP/7z factory class IDs are selected explicitly; host
format/content fallback routing is not exercised. Decoder hash is checked against the exact b2 GUI manifest. It
compiles the actual production open callback class and methods, adding only four
(void) parameter uses to the two no-op bodies so /W4 /WX remain unchanged. The
password method is explicitly a noninteractive E_ABORT facade; all own inputs are
unencrypted. Input is an owned read-only memory IInStream with normal EOF/seek
semantics; extraction uses decoder test mode and null output streams. No output
path, archive deletion, GUI, new Windows setting or untrusted archive is involved.
Fixture hashes checked before/after, source archives and prior evidence untouched.

Eight owned cases were run in both configurations. Normal ZIP244bytes opens with
2indexed items, ErrorFlags0, testS_OK,2successful callbacks. Normal7z312bytes opens
with5items, ErrorFlags0, testS_OK,5successful callbacks. The normal7z is a copy of
the prior qualified owned original, hash-checked. Truncated7z and start-header-CRC
modified7z return S_FALSE on Open, without extraction. These are bounded malformed
archive correctness tests, not exploit or Windows security-barrier tests.

**New prerequisite defect:** removing ZIP central-directory/EOCD leaves two valid
local files. The real decoder Open returns S_OK, count2, testS_OK and zero item
errors, but GetArchiveProperty(kpidErrorFlags) returns VT_UI4 value32
(UnexpectedEnd, bit5; absent central directory). Truncating into the second local
header is stronger: only1item is visible, testS_OK/zero item errors, while the same
archive error flag32 remains. Successful requested/all-visible output cannot
prove the archive is structurally complete. Current Decompress reads item count
and callback completion but never reads these archive status properties.

A separate compiled actual-Decompress replay uses explicit successful-output SDK/
decoder doubles populated with those real observed indexed counts. It returns
OPER_OK and wholeArchiveExtracted=true for both cases, D/R. Five replay cases pass
**reproduction assertions about current behavior**, not safety acceptance. This is
not actual GUI deletion, nor actual output-mode decompression of the damaged ZIP.
It demonstrates the missing qualification input and its current client dataflow;
real decoder test mode supplies the independently observed error metadata.

Declared-volume ZIP (owned header mutation, not a genuine multi-volume set) opens
S_OK with2items and empty volume metadata but has2per-item test errors. Existing
b2 item-error guards cover that reported error path. It is not multi-volume proof.
An adjusted valid central directory indexing only1of2local records reports no
archive error and successfully tests1item. Orphaned/unindexed local records cannot
be reconstructed as archive members from these metadata alone; this audit does
not label that case a fixable parser defect or invent a guarantee to detect every
hidden/orphaned payload. Follow the supported decoder's archive membership model.

## Required next implementation / honest limits

S31b6c7c3b must qualify archive state as well as requested-entry completion before
source deletion: typed/checked GetArchiveProperty error/warning flags or messages,
volume declarations/count/index and failed/unknown property queries must have an
explicit conservative policy grounded in actual supported decoder behavior.
Do not treat missing data as proof of a complete discovered multi-volume set.
Retain ordinary no-delete recovery/Skip behavior. Preserve existing path guards,
CRC/data-error handling, owned source list, cancellation, SDK ABI and Branch gates.
Test new production policy natively including malformed/type/query failures and
real owned damaged/normal decoder cases, host/plugin/dependencies x64 D/R builds
and actual ordinary GUI D/R before local code commit. True supported single-volume
acceptance must remain usable; blanket deletion disablement is not acceptance.
Then c3c qualifies genuine ZIP multi-volume discovery/dedup/missing-volume/Cancel
and separately confirmed complete-owned-set deletion. No current Branch deletion
restriction is relaxed. Remaining Pack/F5 lifetimes and S31/G04/G05 stay OPEN.
