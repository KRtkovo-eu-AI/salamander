## Skutečná cesta klasické operace

1. mainwnd3.cpp CM_COPYFILES/CM_MOVEFILES vybere protější nebo detached target.
   Diskový source vstupuje do FilesAction; archive source do UnpackZIPArchive
   a plugin FS do PluginFSFilesAction. Nejde o jediný společný controller.
2. fileswn8.cpp FilesAction nejprve odmítne `target->IsBranchView()` ještě před
   dialogem a před target prefill. Pinned donor tento guard nemá. Další guard
   omezuje source Branch na ověřené diskové operace; není zaměnitelný s cílem.
3. Ordinary diskový target předvyplní přes GetGeneralPath(path,SAL_MAX_PATH)
   a přidá masku*.*. CopyMoveMoreDialog může tento cíl změnit. Target panel je
   zdroj výchozí hodnoty; následný ručně zadaný explicitní diskový cíl je odlišný
   koncept od implicitního drop cíle. Rozlišení musí zůstat při nové integraci.
4. Po IDOK ParsePath dostává SAL_MAX_PATH, ale jeho current-directory wrapper
   v fileswn9.cpp má vlastní curPath[2*MAX_PATH] a ignoruje FALSE od GetGeneralPath.
   Skutečný diskový GetGeneralPath v fileswn1.cpp při nedostatku místa kopíruje
   zkrácený prefix a vrátí FALSE. Nelze tedy z kapacity cílového path dovodit
   úplnost relative source-directory kontextu. Wrapper je shodný s donorem.
5. Windows target dále prochází SalSplitWindowsPath, který oddělí target/mask
   s přesnými per-item sourceDirectoryW/fullSource identity. Teprve potom
   BuildScriptMain dostává vyřešený path a mask. Branch source odmítá
   PATH_TYPE_ARCHIVE/FS, aby nevstoupil do neověřených callbacků.

## Přetahování a rozdíl kontraktů

DropCopyMove ve fileswn6.cpp před začátkem práce ověří IsRootDropTarget(GetPathW(),
targetPath). branchdroptarget.h dekóduje UTF8-first/ACP fallback a porovná přesný
wide řetězec. NULL/empty/jiný root/child target odmítá. Nejde o obecný Windows
resolver, case-insensitive filesystem identitu ani potvrzení aliasu/reparse cíle.
Testy předchozí S27d5b ani současný audit z této jediné vstupní kontroly
neodvozují bezpečnost libovolného pozdějšího reentrantního callbacku.

Dialogový path obsahuje masku a může obsahovat explicitní uživatelský cíl;
nelze na něj mechanicky použít exact-drop porovnání před ParsePath/SalSplit.
Odstranění blanket Branch target guardu by samo nedodalo owned root/tab snapshot,
fresh modal recheck ani rozlišení implicitního a ručně určeného cíle.

## Nálezy a další malé kroky

- D01: Klasický Copy/Move do Branch target panelu je oproti ověřenému drop rootu
  plošně odmítnutý. S31b5b2 zachytí owned wide root a identitu cílového panelu,
  vymezí diskové target/mask chování a přidá recheck před sestavením operace;
  S31b5b3 pak skutečné GUI Copy/Move/Cancel a změněný target s alias sentinels.
- D02: ParsePath ztrácí source-relative kontext nad519 bytes a nerozlišuje
  failure od úspěchu. S31b5b1 musí použít skutečnou kapacitu a nepředat prefix
  jako platný základ. Převzít wide hodnotu, kde je dostupná; plugin/archive
  virtuální kontexty zachovat a explicitně odmítnout nepodporovaný případ.
- D03: SalParsePath v salamdr5.cpp používá errBuf[3*MAX_PATH+300], ale sprintf
  s IDS_PATHERRORFORMAT obsahuje neohraničené `%s` pro plnou cestu. Přijímaný
  pathBufSize může být SAL_MAX_PATH. Statická délková neslučitelnost je důvod
  k opravě chybové větve v S31b5b1, ne tvrzení o zde reprodukovaném exploitu.

UnpackZIPArchive i Unpack a Pack mají další vlastní Branch target guardy;
nepatří do automatické aktivace Copy/Move a zůstávají pro své ověřené kroky.
