## Změna a její důvod

Donorový CUnpackerConfig::ExecuteUnpacker volí nastavený SupportCustomUnpack
backend; není totožný s vlastníkem archive panel listingu. InitDLL může spustit
callbacky a změnit konfiguraci. Nový interní CWholeArchiveUnpackerSnapshot
zachytí index/type, row pointer a owned Title/Extensions/DLLName spolu s live
plugin pointerem. Přijímá jen procesově stabilní global UnpackerConfig;
neznámý configuration pointer nikdy nedereferencuje. Odmítá invalidní index,
NULL row/metadata/plugin, external/OldType a nepodporovaný custom unpacker.
Plugin index -(Type+1) neprovádí nebezpečnou negaci INT_MIN; Plugins.Get ověří
meze. Owned string allocation failure vrací ERROR_NOT_ENOUGH_MEMORY, jiná
neplatná Capture ERROR_RETRY; před každým pokusem invaliduje starý snapshot.

IsCurrent nejprve ověří global config, index/Preferred a současný row pointer,
až potom čte live row. Kontroluje contents, protože nezměněný MoveUnpacker
kopíruje obsahy mezi stávajícími objekty. Následuje Plugins.Get, pointer equality
a expectedPlugin binding, teprve pak čtení SupportCustomUnpack/DLLName. DLL jméno
se porovnává case-insensitive; jeho změna nebo odebrání/replacement pluginu
invaliduje snapshot. Nejde o transakci, generaci plugin registry ani obecný
object lifetime lease. Neřeší libovolné pozdější callbacky nebo identickou
replacement alokaci se stejnými metadaty.

ExecuteUnpacker má optional backend/source/target context, default NULL.
Panelový kontext bez backend bindingu odmítne; supplied binding musí odpovídat
this config a být current ještě před výběrem dispatch větve. Selected plugin
dostane všechny tři contexts přes concrete UnpackWholeArchive. Ten ověří backend
před InitDLL a znovu po InitDLL spolu s existujícími c4a source/target guards,
před CSalamanderForOperations a SDK callback. Změna vrací FALSE/ERROR_RETRY.
Dosavadní InitDLL/backend failure návraty zůstávají zachované.

Public plugin SDK, virtual order/signatury a skutečný backend callback se
nemění. Změny jsou jen v host zip.h/plugins.h a packers.cpp/plugins1.cpp;
controller fileswn7.cpp, live disk snapshot helper a plugin/vendor sources jsou
beze změny. NULL callers zachovávají plugin i external chování. Guarded snapshot
pro external backend vytvořit nelze; ordinary NULL external cesta stále existuje.
SupportCustomUnpack binding není důkaz bezpečnosti dlouhých cest, whitelist ani
nová Branch capability. Stávající Branch odmítání přímého Unpack se nezměnilo.

## Skutečně provedené testy

declaration/Capture/IsCurrent, ExecuteUnpacker, concrete whole wrapper a actual
MoveUnpacker s actual config-data declaration. Používá explicitní config array,
plugin registry, panel storage, InitDLL a backend/external callbacks jako test
doubles. Neprovádí skutečné I/O ani externí proces; Windows/MSVC /W4 /WX native
Debug i Release po133checks/0failures. Obsahuje konfiguraci changed/removed/
replaced/reordered, title/ext/type/OldType/Preferred mutations, live plugin
remove/replacement/support/DLL změny, source/target forwarding a invalidaci,
foreign config/expected plugin, init/backend error, owned-copy bad_alloc a
legacy NULL contracts. Index INT_MIN a NULL/empty data bezpečně odmítne.

Po InitDLL se testuje18 variant. Negativní kontrola mění jen izolovaný generated
wrapper v paměti: vypne post-Init backend condition, ostatní kontroly ponechá.
149checks/16semantic failures, expected rejection. Počet checks je vyšší kvůli
argument checks v nesprávně zavolaných backend callbacks. Produkční soubory se
negativním testem nemění. Test dokazuje rozlišení backend invalidace od pouhé
úspěšné kompilace; nejde o skutečnou změnu registry v běžícím GUI.
