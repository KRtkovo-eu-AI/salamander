## Změna

UnpackZIPArchive používá CPathBuffer pro subject, path, changesRoot, newDirs
a chybový text. Parser/dialog/append dostávají skutečné kapacity. Plný parsed
prefix má stejnou byte kapacitu jako path; notification memcpy již nezapisuje
do MAX_PATH úložiště. Diskový default pochází z GetPathW přes přesný UTF8
roundtrip. CopyUnpackDestination před kopií kontroluje celou délku a při chybě
nemění výstup; explicitní drop text se nezkracuje na MAX_PATH.

Disková create větev používá UTF8-first/ACP fallback a SalCreateDirectoryExW;
po chybě backendu používá existující RemoveEmptyUnpackDirectoriesW. Definice
cleanup helperu se pouze přesunula před první použití, její tělo je shodné.
Nevstupuje do reparse adresářů, nemaže soubory, prázdné složky odstraňuje best
effort; není filesystémovou transakcí. Znění a volby create potvrzení zachovány.

IsUnpackDirectoryComponentInvalid porovnává ASCII omezení přes unsigned char.
Původní signed char na MSVC odmítal platné UTF8 bajty. Kontroly prvního/posledního
ASCII control/space a koncové tečky zůstávají, prázdný segment má původní
chování. Jiné Win32 zákazy zůstávají v OS/helper/backend kontrolách.

Archive/FS výsledné cíle s byte délkou>=MAX_PATH jsou explicitně odmítnuté
před temp/backend větví; tyto pipeline se nerozšiřují spolu s diskovými cestami.
Delete větev má shodné control flow; její legacy interní buffers se touto
etapou neprohlašují za opravené. Pack, přímé Unpack, listing-owner dispatch,
SDK hlavičky a odložené ChangeDir beze změny. Žádné nové resources; chyby
používají existující lokalizované texty. Dark/light kreslení není změněné.
