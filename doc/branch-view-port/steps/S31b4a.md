## Zjištěná mezera a úzká změna

Připnutý donor i target CFilesWindow::Unpack skládají vstupní archiv až po
CUnpackDialog jako GetPath()+file->Name. Pro Branch výsledky to není skutečný
per-item parent. Živý file pointer se navíc mohl použít po modalu. Donor zde
nemá hotový guarded Branch controller, který by šlo jen zapnout; jde o lokální
integrační opravu navazující na donor GetItemFullPathW a přijatý widepath vzor.

PrepareUnpackArchiveSource zachytí GetItemFullPathW, vlastní UTF8 hodnotu,
ověří lossless wide->UTF8->wide roundtrip a kapacitu SAL_MAX_PATH legacy
archiver API (bytes včetně NUL). Výstup před každým pokusem vymaže, neplatný
source vrací IDS_PATHISINVALID a kapacitu IDS_TOOLONGPATH. Žádný silent
truncation/ACP alias. Unpack zachytí hodnotu před dialogem a předá .c_str()
do ExecuteUnpacker; po dialogu již nedereferencuje CFileData. Dosavadní
Branch source/target refusal zůstává a nový helper nepovoluje žádný backend.
Nedochází ke změně SDK, resources, registry ani Windows zabezpečení.

Zdrojový snapshot není filesystem transakce ani ověření existence archivu;
mezitím smazaný/zamčený/nahrazený soubor může odmítnout backend. Modal panel
identity guards, target cesta, callbacky a command admission jsou S31b4b/c.
Existující pathAlt/fileName/newDir MAX_PATH scratch i MAX_PATH/ANSI Transfer
v CUnpackDialog nejsou touto podetapou opravené. Nelze tvrdit úplný long Unpack.
