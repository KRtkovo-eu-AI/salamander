## Integration and lifetime

CFilesWindow::Unpack owns the exact archive source/parent and live disk source/
target snapshots before its modal dialog. It keeps the actual CUnpackDialog
object after Execute and validates the displayed choice, selected index and
live configuration before capturing the backend. The same contexts are checked
after UpdateWindow, before/after directory creation, at dispatch, and after
backend callbacks. Implicit offered disk roots must still exist; a manually
entered target retains existing resolution behavior and may create directories.
An unused virtual target is not subsequently dereferenced or treated as a disk.

The existing CWholeArchiveUnpackerSnapshot now optionally owns an external
command, arguments and flags; allowExternal defaults FALSE, preserving the
previous plugin-only contract. ExecuteUnpacker forwards the prepared source/
target contexts to both concrete plugin and external backends. Negative preferred
indices are bounded before lookup, and plugin type decoding uses -(Type+1) to
avoid overflowing unary negation for INT_MIN. No unrelated packer change remains.

Begin/EndStopRefresh and thread priority use local scopes. Error paths use the
owned main parent and owned notification paths, with no source getter after a
callback. Focus updates and remaining archive-volume deletion stop when the
context changes, including callbacks from a volume error dialog. Volume encoding
and delete-success policy itself remain the separately planned C05/c7 work.

After InitDLL validation, the concrete plugin wrapper holds the existing
FilesActionInProgress flag through SDK operation context destruction. MoveFiles
sets the same flag before its CheckPath callback. Ordinary and detached tab close
refuse busy panels, including close-menu availability; normal closing works when
the scope ends. These are host lifetime protections, not a new public SDK lease.
Shared SDK virtual order/layout, CFileData and plugin/vendor sources are unchanged.

The legacy external backend still contains narrow MAX_PATH I/O and MoveFiles
buffers. Before creating a target or dispatching it, the guarded controller
therefore rejects source/target text that exceeds its real capacity or does not
decode identically as UTF-8 and the current Windows ACP. The target must also
leave room for the separator, PACK, eight DWORD hex digits and .tmp. Guarded
PackUniversalUncompress captures TEMP with GetTempPathW into heap storage,
verifies exact ACP roundtrip and the same suffix reserve before any temp I/O.
Errors use existing localized Win32 messages; Windows settings are not changed.
Legacy NULL callers retain their existing behavior. This does not qualify legacy
external recursive Unicode/long internal names, reparse handling or arbitrary
third-party backend behavior. Panel snapshots do not make filesystem operations
transactional or prevent another process replacing a file/directory.
