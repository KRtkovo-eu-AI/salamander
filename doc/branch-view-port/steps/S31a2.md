Stav: LOCAL_VALIDATED, 2026-10-25. S31 G02 RESOLVED_LOCAL.
Základ S31a1: `3dd32ce4c1951af83bc787e2e2570e7119fac79b`.

## Převzetí a rozsah

Do `src/fileswn5.cpp::RenameFileInternal` převzat přesný donorový časný Branch
blok: převést název přes MultiByteFileNameToWideBest, delegovat do
RenameFileInternalW a vrátit se před legacy mask/root/ANSI scratch kódem.
Donor: `47661e92d4b3cbe5bb593ae3d75a3f1f698ef413`, část auditního hunku 165.
Běžná legacy větev zůstává původní. Wide přejmenování, cache/remap, invalid-name,
stale metadata a Windows kolizní kontroly se neměnily a neobcházejí se.

Adaptační kód je nový testovací facade, registrovaný v normálním native runneru.
Extrahuje skutečný blok vytváření editace z QuickRenameBegin, celé
HandeQuickRenameWindowKey, nový dispatch blok, celou RenameFileInternalW a
skutečné konverzní/path funkce. Vytvoření Unicode editace je úmyslně neúspěšný
double; fallback vytváří skutečný ANSI Win32 edit pod vlastním skrytým oknem.
Skutečný handler čte tento control a provádí přes wide metodu reálné MoveFileExW.
Nejde o produkční fault-injection hook ani o zpřístupnění ANSI editace uživatelům.

Panel storage/getters a cache-current lookup jsou malé kontrolované doubles;
metadata updater/remap a notifications zaznamenávají volání. Skutečný panelový
remap/getters má samostatný stávající native test 365 kontrol/config. Dialog No
při kolizi, DOS-alias helper a diagnostika jsou explicitní doubles; zde se netvrdí
reálná interaktivní overwrite/DOS-alias zkouška. Obyčejný legacy zbytek je v úzkém
facade nahrazen sentinel počítadlem, protože jej tato oprava nemění; skutečné
obyčejné přejmenování bylo samostatně ověřeno v GUI.

Native I/O má krátký i UTF-16-long Unicode parent. Kontroluje konkrétní nested
soubor a nedotčený root duplicate, ASCII název z reálné ANSI editace a přímý
UTF-8-first vstup s Unicode basename, následnou metadata aktualizaci, stale
identitu bez I/O, odmítnuté oddělovače, kolizi s nedotčenými obsahy, remap/lock
volání a návrat/cancel semantiku editace. Všechny fixture jsou vlastní, pod
unikátním temporary rootem. Cleanup používá explicitní wide extended cesty i při
záměrně neúspěšné negativní mutaci. Zůstává normální /W4 /WX; deprecation define
pro existující legacy strcpy v extrahované metodě odpovídá ostatním native
facade testům a nemění produkční kontrolu ani žádnou runtime assertion.

Při prvním sestavení facade bylo nutné spotřebovat proměnnou unicodeEdit ze
samostatně extrahovaného UI bloku a nastavit stejný CRT deprecation define jako
v ostatních harnesses. První negativní mutace navíc odkryla chybějící failure
cleanup hlubokého fixture; ten byl doplněn, přesně známý vlastní temp adresář
uklizen a negativní zkouška znovu ověřena. Tyto neúspěšné pokusy jsou v evidenci
zachované a nejsou vydávané za pozitivní PASS.

GUI v obou konfiguracích přejmenovalo normal.txt na ordinary-renamed.txt;
v Branch View pouze one-東京/same.txt na one-東京/přejmenováno-東京-🙂.txt.
Obsahy ONE, TWO a ordinary original zůstaly přesné, druhý same.txt se nezměnil,
v kořeni nevznikl odhadnutý cíl a panel po refresh zobrazil správný nový název.
Debug: Windows Dark Mode (experimental); Release: světlé schéma. Skutečné GUI
F2 používá běžnou wide cestu; vynucenou ANSI editaci prokazuje nativní facade,
neprodukční GUI hook se nepřidává. Oba vlastní procesy ukončeny a původní
configstorage.ini obnoveny byte-for-byte přes SHA-256.
