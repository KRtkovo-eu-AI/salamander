# S31a1 — Zapojení SalCreateDirectoryEx do wide helperu

Stav: LOCAL_VALIDATED, 2026-10-25. Nález S31 G01 je pro tento checkpoint uzavřen.
Základ: S31 `a531eb8ca3d9f7ecc8d3d3f75e13bffce91aa17e` nad přijatou S30.

## Rozsah a převzetí

`src/worker.cpp::SalCreateDirectoryEx(const char*, DWORD*)` nyní přesně odpovídá
připnutému donoru `47661e92d4b3cbe5bb593ae3d75a3f1f698ef413`: tělo pouze vrací
`WorkerCreateDirectory(name, err)`. Odstraněno staré ANSI vytváření, podmínka
přechodu na wide podle počtu bytů a pevné MAX_PATH scratch buffery. Živé host/SDK
volání tím používá již převzatou UTF-8-first/ACP a wide implementaci v workerpath.h.
Wide helper ani jeho DOS alias/retry algoritmus se nemění. Public SDK signatury,
vtable, CFileData, registr a Windows security nastavení zůstávají beze změny.

Nový adaptační kód je pouze regresní harness. Extrahuje skutečné tělo host
wrapperu z worker.cpp a SDK delegátu z zip.cpp; nepíše jejich náhradu. Používá
existující MSVC discovery a deadline z safe_file_paths_tests.py, skutečný
workerpath.h a reálné Win32 I/O. SDK stack-trace macro je explicitní no-op double.
Test je registrovaný jako create_directory_wrapper_tests v normálním native
runneru; Configuration se předává stejně jako ostatním generated native testům.

Nový native test prochází host i SDK vstup: běžné ASCII, Unicode leaf, Unicode
parent a více Unicode komponent, diakritiku/CJK/surrogate pair, UTF-8 délku nad
MAX_PATH při kratší UTF-16 cestě, UTF-16 cestu nad MAX_PATH, child pod dlouhou
cestou, přesné trailing-dot/trailing-space identity a nepřítomnost zkráceného
sourozence. Dále kontroluje relativní Unicode cestu pod krátkým cwd, legacy ACP
fallback při nevalidním UTF-8, existující adresář, file collision a nedotčené
obsahy, missing parent, empty/null vstup a nepovinný error pointer.

DOS alias větev má deterministické API doubles pro dočasnou kolizi, opakování,
obnovení původního jména a rollback při neúspěšném obnovení. Tyto čtyři assertions
nejsou skutečný 8.3 volume test; nastavení generování DOS aliases se neměnilo.
Všechny ostatní path/I/O scénáře používají skutečné Windows soubory/adresáře pod
vlastním temporary rootem, se samostatným extended-wide oracle a ověřeným cleanup.

GUI test vytvořil `ascii` a `ascii/žluťoučký-東京-🙂`, zobrazil podadresář v panelu
a nezávisle ověřil jeho přesný název a nezměněný keep.txt. Debug používá Windows
Dark Mode (experimental), Release světlé schéma. Long path průchod skutečným
char wrapperem dokládá native fixture; GUI nepřepínalo násilně MakeDir na ANSI
fallback, protože běžný dialog může používat vlastní wide cestu. To se neuvádí
jako GUI důkaz konkrétního fallbacku. Oba vlastní procesy skončily a původní
configstorage.ini byly obnovené byte-for-byte přes SHA-256. Testovací soubory
zůstávají pouze v ignorovaném vlastním build fixture.
