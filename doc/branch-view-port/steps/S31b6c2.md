## Implementace a důvod adaptace

PrepareUnpackArchiveSource má volitelný interní std::string* sourceDirectory.
Při vstupu vyprázdní source i požadovaný parent. Zachovává předchozí exact
GetItemFullPathW, UTF8 roundtrip a SAL_MAX_PATH byte-capacity refusal. Parent
vzniká z téže wide identity přes již existující donor SalPathFindFileNameW,
nikoli z GetPathW panelu nebo root+basename odhadu. Zachová drive/share separator,
odmítne chybějící leaf/parent; UTF8 parent musí přesně roundtripovat. Výstupy
se publikují teprve po úspěchu obou konverzí. Původní source-only native volání
se zachovaným default NULL stále prochází stejnými původními assertions.

Controller zachytí archiveSource a sourceDirectory společně před modalem.
Odstraněna jen druhá konverze panelového GetPathW; tělo od CPathBuffer včetně
default/alternate/stem/mask/SalGetFullName, I/O, delete a notification logiky je
přesně stejné jako parent. Nová skutečná relativní base odpovídá parentu archivu
a její trailing separator se nevypouští na drive/UNC root. Jde o adaptér pro
budoucí Branch source, současné ordinary chování zůstává ověřené.

SalPathFindFileNameW je exact donor helper v common/widepath.cpp; soubor ani
veřejné rozhraní se nemění. Žádné nové generic API, SDK vtable, MAX_PATH path
buffers, plugin/backend změny, povolení Branch source/target nebo volume deletion.
Snapshot textu není garance životnosti panelu, cíle nebo zvoleného backendu.

## Skutečné GUI a readback

Debug Windows Dark Mode (experimental), Release light. Vlastní isolated RegFile
profily z ověřené ZIP konfigurace, bez změny Windows security. Python zipfile
vytvořil vlastní archiv archiv-東京.zip v krátké Unicode source složce. Obsah:
ascii.txt, odlišné one/same.txt a two/same.txt, žluťoučký-東京/東京-😀.txt; přesné
per-config payload SHA256 v manifestu. Source a target mají vlastní keep.txt.

V obou konfiguracích actual AltF9 při obou preferences FALSE: prázdný default,
combo nabízí exact protější target. Cancel beze změny celého stromu. Druhý
izolovaný profil má obě preferences TRUE: default target\archiv-東京 a alternativa
archiv-東京, oba Unicode názvy správné. Opět Cancel a přesný baseline strom.
Další AltF9 ve stejném profilu: explicitně typed relativní rel-東京\80a\80b.
ZIP celý archiv úspěšně rozbalil pod skutečný source parent: output root260/262
UTF16 (268/270UTF8), souborové cesty přes260. Readback všech4file hashes, přesné
relative names, celý tree, archiv a oba sentinels souhlasí, nikde další výstup.
Delete archive checkbox po celou dobu vypnutý, žádné GUI mazání/overwrite potvrzení.
Po operaci hlavní panel zůstal funkční, neprováděla se navigace do dlouhého rootu.

První Debug launch použil testovací INI s BOM a profilem s jinými line endings,
takže místo připraveného profilu zobrazil Welcome. Vlastní proces ukončen před
pokračováním, testovací INI opraven na ASCII bez BOM a RegFile na původní CRLF;
pak všechny scénáře provedena s korektním profilem. První launch metadata jsou
zachována, nejsou vydávána za úspěšný test. Produkční patch/binárky se neměnily.
Varování o chybějícím salmon.exe patří izolovanému runtime, bylo zavřeno; žádný
pád rozbalování ani zásah do systémových bezpečnostních dialogů nebyl pozorován.
