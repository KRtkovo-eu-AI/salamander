baseline důkaz. Nejde o odhad podle staré MENU-only zprávy z jiné etapy.

Donor již má stejnou alokaci NameW i host projekci, jež nové ABI pole nečte.
Host AddFile/AddDir záměrně kopírují pouze historické položky a NameW nastaví
NULL, aby nečetly za starým CFileData. Úspěšné předání proto přebírá Name a
PluginData, nikoli NameW alokované moderním pluginem. Dosavadní error helper
NameW uvolňoval jen při neúspěchu; na úspěšné cestě unikalo.

CListedNameWGuard v AddFileDir nyní vlastní tento nepřebíraný vstup po celý
život lokálního fd. Destruktor uvolní NameW i při úspěchu či unwind. Dosavadní
error helper stále nejprve uvolní a vynuluje pointer, takže guard podruhé
neuvolňuje. Vstup NameW během AddFile/AddDir zůstává dostupný, UTF8 Name i
PluginData přecházejí do hostu beze změny. Host projekce, SDK layout/vtable,
allocator Name, engine, parser ani heap filtr se nemění. Guard je adaptace
současného přijímacího kontraktu, nikoli povolení číst NameW ze starých pluginů.
Budoucí změna přenosového kontraktu musí upravit i toto vlastnictví.
