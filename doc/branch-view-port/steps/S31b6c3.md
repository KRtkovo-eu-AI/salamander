## Implementace

GatherItems dostává explicitní archivePathCapacity a předává ji oběma existing
SalamanderGeneral->SalPathAppend voláním i recursive callu. Selhání append
teď vyvolá existující IDS_ERRADDFILE_TOOLONG/IDS_ERRADDDIR_TOOLONG a OPER_CANCEL,
ne přeskočení file/podstromu s OPER_OK. SalPathAppend při odmítnutí nemění buffer;
při úspěchu se parent obnoví po vytvoření recordu a po recursive return včetně
chybových návratů. Žádné skládání odhadované nebo zkrácené cesty, nepřidává se I/O.

Původní pořadí files/directories, maska, metadata0 implicit-directory pravidlo,
private FileData pointer a IsDir se zachovávají. Lokální addItem lambda centralizuje
obě pevně spojené allocation větve: new(std::nothrow) se stávajícím NULL/OOM
odmítnutím, debug new macro vypnuto/obnoveno jen kolem tohoto výrazu. Při chybě
TIndirectArray::Add se nepřevzatý record uvolní a vrátí OOM/OPER_CANCEL; shared
array Add mění Count a přebírá pointer jen ve State==etNone, jeho zdroj se nemění.
Počáteční špatný array state také odmítne operaci. Existující testy se neoslabují.

UnpackWholeArchive místo stack char archivePath[MAX_PATH_LEN] používá jeden
malloc(SAL_MAX_PATH) buffer s explicitním NULL/Error a free po práci se seznamem.
Decompress zůstává uvnitř podmínky úspěšného GatherItems, ret začíná FALSE;
neúplný seznam není předán enginu. Ostatní wrapper/backend/deletion/password/
listing/output části pluginu jsou beze změny (audit porovnává oba změněné bloky
proti přesnému parent souboru). Žádná veřejná SDK, vendor konverze nebo lifetime
garance se nepřidává. Kapacita je byte limit; output guard nadále zvlášť ověřuje
kombinovaný target+entry a relativní komponenty před prvním I/O.
