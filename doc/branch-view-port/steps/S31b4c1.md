## Změna a hranice

ZipExtractTargetError kontroluje přesný target length, skutečný entry řetězec,
hranici RootLen a případnou náhradní basename. Před původním SplitPath a
ručním appendem odmítne overflow včetně oddělovače a NUL pro obě velikosti
existujících caller buffers. Navíc ověří celou wide extended Win32 cestu proti
32767 limitu. V ExtractFiles zůstává skip/skip-all/cancel chybová větev;
kapacitní chyby hlásí IDS_TOOLONGNAME3, neplatný název existující lokalizovaný
IDS_ERRCREATE s Win32 ERROR_INVALID_NAME, low memory IDS_LOWMEM. I single-entry
ExtractSingleFile má vlastní guard před prvním zápisem; vstupní target kopie
UnpackOneFile/ExtractFiles jsou zvlášť ohraničené.

Před I/O odmítne prázdné/dot/dotdot komponenty, absolutní/drive/stream zápis,
zakázané Win32 znaky, koncovou tečku/mezeru a DOS device jména včetně jejich
přípon i COM/LPT superscript1/2/3. Chrání před novými významy extended prefixu;
není to obecný sandbox nebo filesystem transakce. Existující reparse cíle
a souběžné změny filesystému se tím nemění ani neprohlašují za izolované.
ProcessName nadále normalizuje původní archive entry text před touto vrstvou;
native test ověřuje guard nad post-normalization názvy, nikoli ZIP parser.
CRC-only Test režim drží byte-capacity guard, ale nepotřebuje výstupní cestu
ani její bezpečnostní admissibilitu, protože neprovádí destination I/O.

SetZipExtractAttributes a DeleteZipExtractOutput používají ZipPathToWide
(UTF8-first/ACP fallback, extended prefix), zachovávají OS chyby. Běžný cleanup
nesmí sám zrušit read-only zákaz; pouze již existující CRC failure větev
vyžaduje vymazání vlastního poškozeného výstupu a odstraňuje jediný RO bit.
Původní engine CRC/flush/close/cancel/password/AES i SafeFileCreate rozhodnutí
zůstávají. Optional CWD změna používá wide API, zpětná obnova zůstává původní
CZipCommon. Ostatní ZIP operace, SFX extractor, unknown pluginy ani host
Branch command admission se nemění. Žádné registry/security/SDK/resource změny.
