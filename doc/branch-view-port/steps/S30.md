## Audit rozsahu a koherentní checkpoint

Pořadí bylo před implementací zapsané do plánu: watcher/refresh integrace,
aktivace donorových testů a společná nativní/GUI/performance brána. Scheduler,
SameSnapshot, bounded previews, comparator a časové řezy asociací už existují
ze S25/S26/S28. Nekopírují se znovu a nevzniká další scheduler. Jde o jeden
sestavitelný checkpoint s následujícími propojenými částmi:

- Převzaty donorové PreparedWatchPath, wide FindFirstChangeNotificationW a oddělené
  klíče |recursive / |directory. AddDirectory, ChangeDirectory a EnsureWatching
  volí rekurzi pouze pro Branch View. Běžný panel nad stejným rootem nadále
  dostává vlastní nerekurzivní watcher. Ruší se dočasný zákaz automatic refresh.
- Target adaptace PrepareWatchPath explicitně rozlišuje platné UTF-8 a legacy ACP;
  bez ní donorový implicitní ACP převod poškozoval Unicode cestu targetu.
- Integrační mezera mimo donor: CChangeNotifData a soukromá fronta nyní vlastní
  celý std::string. Producent zachová best-effort chování při std::bad_alloc;
  spotřebitel swapem převezme cestu bez alokace, odemkne a ponechá ji živou přes
  všechny callbacky. Zachováno LIFO pořadí, timestamps, flags i callback API.
  Do TDirectArray se nevkládá objekt se std::string. Veřejné SDK se nemění.
- Branch completion oznámení používá TRUE jako automatický refresh stejně jako
  snooper. Neobnoví Stop; Ctrl+F9 zůstává explicitní ruční obnovení. Stará dočasná
  manual-only source assertion je nahrazena přesnou kontrolou scheduleru a flagu.
  Nativní notification oracle nově vyžaduje TRUE a má další long/prefix testy.

Třináct auditovaných donorových bloků je EXACT (osm algoritmů včetně již
převzatých a pět watcher bloků); zbývající hunks/odchylky jsou v REUSE.tsv.
Funkce pro výběr/fokus, reentranci, stale generation, ikonové lifetime a S28a
preferenci absolutní/relativní Path se nemění. Experimentální gate zůstává
výchozí vypnutý. Žádné nové UI texty ani změny překladů.

## Skutečné GUI a vlastní měření

Debug používá Windows Dark Mode (experimental) schéma, Release světlé schéma;
oddělené vlastní profily a fixture. gui-observations.json obsahuje 17 skutečně
pozorovaných scénářů (7 Debug, 10 Release), nikoli odhadnuté PASS z native testu.

V obou konfiguracích se nový obrázek v hluboké dlouhé Unicode cestě objevil bez
ručního zásahu. Během průběžného vytváření tisíců souborů zůstával viditelný starý
snapshot. Stop během přípravy asociací zobrazil refresh stopped a zachoval
30005 položek Debug / 17755 Release. Další změna v hluboké cestě ani přepnutí
panelu stav neobnovily (pozorováno po 19/22 s). Ruční Ctrl+F9 sken znovu spustilo;
finální počty 40006 Debug / 25006 Release souhlasily se samostatným scannerem.
Druhý panel reagoval během přípravy 40006/25006 položek; zaznamenaných 624/399 ms
zahrnuje input i Computer Use capture, není to izolovaná latence aplikace.

Release následná automatická změna zvedla počet na 25007 a zachovala přesný
vybraný/fokusovaný Unicode same.png 410x290 (1033 bytes), ostatní stejné basename
zůstaly nevybrané. Návrat k Debug instanci měl úplný stabilní výsledek. Release
restart bez process gate otevřel obyčejný root a Ctrl+B Branch View neaktivovalo.

Oddělené indikátory výkonu (nejde o slib procentního zrychlení celého GUI):

- Traversal + drain skutečného scanneru, samostatný /O2 probe nad vlastními
  připravenými stromy: 40006 souborů / 138,327 ms a 25006 / 86,410 ms, bez chyb.
  Oba kořeny měří tentýž Release probe, nejde o porovnání Debug versus Release.
- Preparation: původních 17 donorových testů ověřuje časový a query cap, pokračování
  a invalidaci při callbacku. GUI ověřilo skutečné pomalejší nové asociace,
  ovladatelnost a Stop. Izolovaný čas třetích shell providerů se netvrdí.
- Publication: původní native testy potvrzují caps 2048/8192 a žádné opakované
  publikování rostoucích plných prefixů. Access-only SameSnapshot nad skutečnými
  stromy: true / 8,220 ms a true / 5,157 ms. Pure UI publication ms se z hrubých
  screenshot intervalů neodvozuje.
- 175000 syntetických dlouhých Unicode řádků: přesné stejné pořadí při řazení
  oběma směry; původní kopírující/nový comparator časy jsou v Debug/Release logu
  branch_view_tests-run-*.stdout.log. Vlastní běhy, ne donorových 87 procent.

## Hranice a uzavření

Běžné panely a oddělená nerekurzivní watch semantika byly ověřeny. Archivní a
plugin GUI se neopakovalo; jejich callback signatury a virtuální cesty zůstávají,
queue předává původní text beze zkrácení a bez diskové konverze. Legacy scratch
limity v běžné/archive notification consumer větvi jsou mimo Branch watcher port;
nejde o tvrzení kompletní dlouhé podpory všech pluginů. SMB/offline/provider
latence není garantovaná. Stop neruší právě probíhající cizí shell callback.

Vlastní GUI procesy ukončeny, původní configstorage.ini obnoveny přes SHA256,
osm původních obrázků beze změny. LongPathsEnabled=0, bezpečnostní nastavení,
SDK veřejné hlavičky, CFileData layout, workflow, donor a SOURCE.json beze změny.
S29 VSIX oprava zůstává v přijatém základu. Žádné cizí soubory/cache/logy/binárky
se necommitují. Evidence ../evidence/S30 váže runtime.patch, build/test/GUI hashes
a měření na lokální checkpoint (final-audit.json, committed-validation.json).
