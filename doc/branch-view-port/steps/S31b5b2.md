# S31b5b2 — owned diskový target a opětovné ověření identity

## Implementace

CFilesActionDiskTarget je privátní helper ve fileswn8.cpp, bez SDK/header ABI.
Zachytí přesnou wide cestu, bezeztrátový UTF8 default včetně masky, tab ID,
Branch stav a generaci. FindLive porovnává uloženou adresu pouze s živými
položkami registrů panelových a detached karet. Až nalezený objekt dereferencuje;
shodná adresa nestačí bez shodného tab ID. Pokud byl target viditelnou levou
nebo pravou kartou, její přepnutí také zneplatní snapshot. Inaktivní karta
explicitně vybraná detached chooserem se nepovažuje za neplatnou jen kvůli
neviditelnosti. Nové zachycení invaliduje předchozí snapshot ještě před pokusem.

FilesAction zachytí target před CheckPath a jeho potenciálními callbacky.
Běžný diskový default již nebere přes ignorovaný GetGeneralPath výsledek;
kopíruje úplný předem zkontrolovaný owned root+mask. Kontroly probíhají před
Copy/Move dialogem a po IDOK, po dalších warning/UpdateWindow hranicích, po
ParsePath, po výsledném CheckPath (zahrnuje předchozí SalSplitWindowsPath),
před BuildScriptMain a před spuštěním po analýze/free-space promptu. Při změně
se operace zruší přes původní cleanup cestu s lokalizovaným Windows ERROR_RETRY.
Nejde o transakci nad skutečným filesystemem ani filesystem file-ID snapshot.

Ordinary explicitní cíl zadaný uživatelem není vázán na root cílového panelu.
CopyToSelectedDirs si uchovává dosavadní explicitní seznam cílových cest;
nová kontrola chrání identitu panelu, nikoli neměnnost jeho výběru. Archive/FS
routing se nemění. Branch target entry guard zůstává; helper není capability
ani povolení celé Branch operace. DropRoot helper ani donor/source piny neměněny.

## Další konkrétní předpoklad

Při čtení SalSplitWindowsPath (salamdr5.cpp) nalezen `changesRoot[MAX_PATH]`
a memmove délky `secondPart-path` při tvorbě nových cílových adresářů. Resolver
přijímá SAL_MAX_PATH; tento nesoulad musí být prověřen/opraven před tvrzením
plného long-target creation. Je to statický nález, nikoli reprodukovaný nový pád.
Netýká se odložené opravy ChangeDir. S31b5b3 nejprve vyřeší tento malý kapacitní
předpoklad a root/mask preflight před SalSplitWindowsPath (ten může zapisovat
adresáře); teprve potom aktivace a plné Copy/Move/Cancel se sentinely.
