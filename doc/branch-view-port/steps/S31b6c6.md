## Integration and policy

Adapt the donor Unpack/dispatch integration using the already qualified ZIP and
7Zip backends and existing directory-mode disk target snapshot. Both ordinary
and Branch disk sources can target Branch View. Destination is the captured
collection root, never the parent of its focused item. Preserve archive-subdir
preference: only the exact offered root or its one generated archive-stem child
is allowed. With the other-panel preference FALSE, the user must choose the
alternate offered Branch target; the source-parent default is refused. Ordinary
targets retain their existing manual target behavior.

CWholeArchiveUnpackerSnapshot now owns BranchTargetDirectory, cleared on Capture.
BindBranchTarget validates the live qualified backend and current directory-mode
target, UTF-8 text/capacity, exact root or single child and existing wide root.
Child separators, ADS/wildcards, trailing dots/spaces and parent aliases fail
closed. The controller also compares the exact resolved path with the exact
offered path before binding or creation; the binder does not authorize arbitrary
children chosen outside that controller. ValidateBranchTarget checks bound bytes,
current target/backend and GetFileAttributesW directory existence, adding an
extended prefix for Win32-long roots. It runs during controller callbacks, in
ExecuteUnpacker and independently after InitDLL before the SDK operation context.
Missing/changed context returns ERROR_RETRY1237; manual Branch redirection returns
localized ERROR_NOT_SUPPORTED50. No missing Branch root is implicitly recreated.
These checks are not a filesystem transaction and do not guarantee atomic path
identity against concurrent filesystem replacement after validation.

Either Branch side requires the qualified current bundled ZIP/7Zip backend and
no archive deletion. Source/target lifetime, tab close/busy/scan/generation,
modal configuration and refresh guards remain in force. Source focus stays
suppressed for Branch sources; target never receives a fabricated root-relative
focus. External/custom backends and virtual targets are not newly admitted.
Public SDK/vtables, CFileData, plugin/vendor code and native runner are unchanged.
This is local staged integration rather than a new framework or DLL authentication.
