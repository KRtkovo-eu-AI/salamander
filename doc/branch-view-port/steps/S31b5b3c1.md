# S31b5b3c1 — atomické načtení Copy/Move cíle

CCopyMoveMoreDialog dříve ignoroval FALSE z GetControlTextUtf8, který při chybě
mohl vyprázdnit nebo zkrátit caller buffer. Potvrzení pak pokračovalo do historie,
převodu voleb a resolveru; prázdná cesta tam má vlastní implicitní sémantiku.
Před rozlišením ručně zadaného a implicitního Branch cíle je nutné tuto ztrátu
informace odstranit. Tato podetapa ještě Branch destination nepovoluje.

Dialog nyní vytváří Unicode resource controls. Při ttDataFromWindow načte
úplnou cestu do vlastní std::string přes již existující ReadUnpackDialogPath.
Ověří skutečnou byte kapacitu i přesný UTF16/UTF8 roundtrip. Selhání označí IDE_PATH
jako chybu a vrátí se před změnou Path, history, criteria, scheduling, keep-paths
nebo transfer/conflict modes. Záměrně prázdný vstup zachovává stávající controller
sémantiku. Missing control používá existující transfer error bez dvojí hlášky.
Selected-directory list režim není závislý na editované cestě.

Historie i počáteční text jdou přes wide Win32 API, s UTF8-first/ACP fallback
pro původní char vstup. Edit-only fallback používá stejné atomické čtení.
ReadUnpackDialogPath byl pouze přesunut před první sdílené použití; jeho tělo,
Unpack constructor a Transfer jsou přesně stejné jako v parent checkpointu.
Chyby používají existující lokalizované texty a SalMessageBox. Žádná změna
SDK hlaviček/ABI, Windows zabezpečení či registrů, drop helperu nebo Branch
controlleru. LongPathsEnabled zůstává0; nastavení nebylo měněno.
