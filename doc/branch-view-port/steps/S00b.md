Stav: DONE — oprava evidence a cleanup, 2026-10-12. Předkrok vznikl ze
skutečného GUI smoke S00a; S01 nezačala. Baseline první prázdný config zůstává

## Konkrétní blokace a původ

Debug x64 host z TARGET_SHA při startu hlásí z `C__Handles::CheckClose`
(`src/common/handles.cpp:864`) volání `DeleteObject` z
`CIconList::ReplaceIcon` (`src/iconlist.cpp:483/485`), handle nenalezen.
`GetIconInfo(hConvertedIcon, &convertedInfo)` vzniklé bitmapy nezapisuje do
trackeru. Zkontrolovat i `CopyImage`, `DestroyIcon`, druhé `GetIconInfo` a BAIL
cleanup stejné funkce; nepředpokládat, že dva zachycené dialogy jsou úplný seznam.
Připnutý donor má totožný `iconlist.cpp`; žádná oprava se z něj nepřenáší.

## Nejmenší rozsah

Reprodukovat baseline, sjednotit evidenci vlastnictví a uvolnění těchto GDI
objektů podle existujících tracker pravidel. Nepřidávat obecný framework,
neměnit veřejné SDK ani široce vypínat `HANDLES`. Explicitní raw Win32 cleanup
je případně přípustný jen pro prokazatelně netrackované API objekty; zdůvodnit
volbu proti existujícímu `HANDLES_ADD_EX` mechanismu. Žádné hunks S01/S02.
Do mapy zapsat nový adaptační kód a důvod až se skutečnou implementací.

Úzký audit při opravě: `GetFileIcon`/`GetFileIconForPanel` vracejí externě
získaný, netrackovaný HICON. Existující `GetRootPathIcon` jej zapisuje u volajícího;
icon reader naopak používá NOHANDLES cleanup. Nové startup call sites v
`CAssociations::GetIcon` a `CreateSimpleIconListForPixels` registraci
vynechaly (další skutečný Debug dialog v `icncache.cpp:1183`). Doplnit ji pouze
u těchto vlastníků, ne změnit veřejnou návratovou smlouvu. Dočasné externí ikony
v `geticon.cpp` a odmítnutá stale-DPI ikona v `fileswn1.cpp` musí zachovat
stejný netrackovaný cleanup jako jejich ostatní větve. Nejde o cache opravu PR #10.

Shutdown audit dále prokázal dvě owned ikony z `SetDPIAwareWindowIcon`:
`CWindow` se odpojuje už při WM_DESTROY, takže hlavní okno musí zde zavolat
existující `ReleaseDPIAwareWindowIcons`. Po normal-panel copy smoke obsahoval
tracker ještě šest štětců z `gui.cpp` (tracked create / raw delete) a jednu
duplicitní registraci z wide copy větve `worker.cpp` (tracked CreateFileW plus
společný HANDLES_ADD_EX). Sjednotit pouze tyto konkrétní páry; žádné nové
path/DPI/rendering/copy chování ani změna error/fallback smluv.
