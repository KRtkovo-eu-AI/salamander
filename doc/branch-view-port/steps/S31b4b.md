## Adaptace proti donoru a chování

Navazuje na připnutý PR769 a jeho CUnpackDialog/CFilesWindow::Unpack,
GetItemFullPathW a widepath vzor. Donor nemá hotový bezpečný Branch Unpack
controller; tato lokální integrace opravuje doložené krátké/ANSI mezivrstvy.
CUnpackDialog dostává skutečnou kapacitu, používá Unicode controls a načte
celou délku přes GetWindowTextW. Lossless wide->UTF8->wide roundtrip a byte
kapacita se ověří před jakoukoli změnou caller path/backend/delete flagu;
neplatný vstup hlásí existující lokalizované IDS_PATHISINVALID/IDS_TOOLONGPATH.
Prázdný target zůstává platný pro následný controller default.

Unpack zachytí owned UTF8 source directory před modalem, target default bere
z GetPathW, používá CPathBuffer pro path/alternate/filename/subject/nextFocus.
Wide basename se nezpracovává ACP case tabulkami: zachová přesný NameW včetně
case; legacy FileNameFormat zůstává pro ANSI basename. Název podadresáře se
odvozuje z kompletního UTF8 basename bez poslední neprázdné přípony. Kapacita
appendu se kontroluje; subject má typovaný wide formát. SalGetFullName dostává
skutečnou pathBuffer.Capacity(); CheckAndCreateDirectoryW vrací kompletní
první vytvořenou složku. Optional NextFocusName[MAX_PATH] je při příliš velkém
názvu vyprázdněný, nikoli zkrácený; nevstupuje do I/O.

RemoveEmptyUnpackDirectoriesW iterativně prochází pouze tento nově vytvořený
strom přes wide extended APIs; files/reparse adresáře vynechá a zezadu zkusí
RemoveDirectoryW, které uspěje jen pro prázdnou složku. Neodstraňuje soubory,
neupravuje attributes, nemění CWD a nepřechází přes junction. Best effort
není filesystem transakce; souběžná změna filesystému může cleanup znemožnit.
Není nový MAX_PATH path scratch, SDK/resource/security/registry změna.
File mask zůstává dosavadní MAX_PATH mask buffer (není filesystem cesta).
Source disk/non-null target guard je explicitní; Branch source/target zůstává
odmítnutý. Delete archive následná legacy větev se zde nezpřístupňuje pro Branch.
