# S31b5b3a — úplný existující prefix pro directory notification

## Konkrétní oprava

SalSplitWindowsPath předával memmove délky secondPart-path do changesRoot[MAX_PATH].
Vstup může mít mnohem delší existující prefix, a to i jen kvůli UTF8 byte délce.
Buffer nahrazen owned std::string přesného prefixu. Konstrukce proběhne před
prvním pokusem vytvoření adresáře; prefix zůstane platný přes mutace split bufferu.
Do PostChangeOnPathNotification předá c_str celého řetězce. Host notification sink
(mainwnd3.cpp) kopíruje text do CChangeNotifData, takže caller pointer neuchovává.
Zůstává stejné includingSubdirs=FALSE i notification při selhání některé tvorby.

Žádná nová podpora Shell, změna registrů, vypnutí confirmation, SDK/header ABI,
ANSI fallback či Branch admission. Oprava nemění SalSplitGeneralPath ani jeho
mask/creation rozhodování. Původní nález je statický, nepouštěl se nebezpečný
původní overflow kód. Nový kód byl ověřen skutečnými filesystem operacemi níže.

## Další předpoklad S31b5b3b

SalSplitGeneralPath vkládá další NUL a někdy přidá backslash + universal mask.
Nynější interní signatura nepřijímá skutečnou caller kapacitu; SDK komentář
spl_gen.h garantuje pouze minimum2*MAX_PATH, zatímco core má SAL_MAX_PATH.
Před aktivací Branch cíle doplnit kontrolu růstu/kapacity bez změny vtable SDK,
explicitní bezpečné odmítnutí nedostatku místa a testy hranic/cancel. Není správné
považovat81 kontrol běžných/dlouhých cest za důkaz všech mezních kapacit.
Poté preflight Branch výsledného rootu/mask před split/create a ověřená aktivace.
