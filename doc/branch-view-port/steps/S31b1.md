# S31b1 — Otevření souboru jako archivu podle obsahu

Navazující [S31b1a](S31b1a.md) prokázala starší donorový 7zip leak a opravila
jej bez změny heap filtru či legacy ABI. Níže zachovaný stav je historický
checkpoint před touto opravou; archive-entry část G04 je nyní RESOLVED_LOCAL.

Stav: FUNCTIONAL_CHECKPOINT_WITH_OPEN_HEAP_FINDING. S31b1 není plně uzavřená.
Parent `7df592ee99ef98805a8ea4e2ea55a6ad5db3fd90`, branch
`fix/pr769-s31b1-archive-entry`. Goal S31 ACTIVE, bez push/PR.

## Implementace a původ

Donor `47661e92d4b3cbe5bb593ae3d75a3f1f698ef413`, fileswn0 hunks 43–44:
TryEnterFileAsArchive používá GetItemFullPathW, UTF-8 a vybraný plugin v
ChangePathToArchive. Ctrl+PgDown tak otevře podporovaný obsah i pod jinou
příponou. Dočasný Branch guard nahrazuje ověřená implementace.
Lokální adaptace vlastní vstupní řetězce a před/po CheckPath i probe kontroluje
typ panelu, wide kořen, Branch generaci a cache identitu. Po callbacku již
nedereferencuje případně zrušený řádek. noChange začíná TRUE pro časný Cancel
uzamčeného tabu. Původní SAL_MAX_PATH byte limit zůstává; nový path stack buffer
nevznikl. Bez ExecuteAssociation fallbacku a bez rozšíření SDK/plugin admission.

GUI odhalilo skutečné CRT assertions ve třech dalších místech: DirectoryLineSetText
(520 bytes), GetGeneralPath pro tab caption (520) a CanUnloadPlugin (260).
Záhlaví a obecná archive cesta používají std::string; GetGeneralPath při malé
kapacitě vrací FALSE a ukončený platný UTF-8 prefix přes existující helper.
Unload používá dynamický zapisovatelný vector, zachovává check/cut/no-reconnect,
rescue fallback i FALSE při nemožném přepnutí na disk. Legacy pluginFS scratch
v ostatních větvích není tímto checkpointem certifikován jako long-path ready.

## Ověření

- Native actual source extraction: **267 checks/config Debug i Release PASS**.
  Skutečné CtrlPgDn/TryEnter, probe dispatch, SDK version gate, ZIP signature wide
  I/O, UTF8 copy, archive header/general path a used-plugin unload blok.
  UI, plugin loading, 7zip engine a disk switch v native fixture jsou explicitní
  doubles; skutečné pluginy ověřuje samostatné GUI. Nejde o celý host v harnessu.
- Čtyři dočasné mutace mimo Git (wrong basename, generation, post-probe context,
  header truncation) každá detekována assertion failure. Produkční zdroje se pro
  negativní běh nemění. Všechny dřívější assertions zachované.
- Source archive contract PASS, transitions28, operationsAll20, Branch19 PASS;
  actual getters365/config PASS (před poslední čistě unload opravou).
- Host + dependencies v145 x64 warnaserror Debug/Release PASS. ZIP a 7zip D/R
  buildy včetně engine/resources PASS před poslední host-only unload opravou.
- GUI šest případů/config: ordinary ZIP, dva same.payload v různých Unicode
  podadresářích s odlišným obsahem, 7zip pod UTF8 byte-long a UTF16-long cestou,
  plain text odmítnut. Všechny přípony .payload; návrat do původního Branch
  seznamu po každém validním archivu. Debug cesty 227/427 a 291/595 UTF16/UTF8;
  Release229/429 a293/597. Skutečné plugin listingy, nikoli native doubles.
  Tato celá matice proběhla před poslední opravou unload; příslušné launch/patch
  hashe zůstávají historické, finální open/close je veden zvlášť.

Finální open/close: Debug zobrazil LONG-SEVEN.txt a unload overflow se již
neopakoval; při shutdown zůstává Heap Message. Release po finálním otevření LONG-SEVEN.txt skončil bez assertion/dialogu; oba
procesy ukončené. 12 fixture souborů hashově beze změny a configstorage obnoven
byte-for-byte. Výsledky jsou vázané na finální patch. Před S31b2 následuje S31b1a — objasnit heap hlášení
proti odpovídajícímu ordinary 7zip/baseline scénáři; případnou regresi opravit.

Debug při ukončení původní funkční matice ohlásil Heap Message. Následná dočasná
instrumentace pouze zapsala CRT report (žádná změna filtru/assertion). Kontrola
bez operace a ordinary ZIP skončila bez zprávy. Odchod s dlouhým 7zip archivem
odhalil výše uvedený unload overflow; ten je opraven a diagnostická změna heap.cpp
obnovena byte-for-byte. Dřívější MENU-only baseline z S27f08b1 nelze automaticky
vydávat za důkaz příčiny této konkrétní zprávy. Memory-clean status se netvrdí.
