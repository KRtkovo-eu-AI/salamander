# S31b5b3c2 — implicitní cílový root/mask před split/create

FilesAction používá zachycený diskový panel jako výchozí cíl dialogu. Jiná
ručně zadaná cesta má vlastní legacy resolver s relativním source kontextem.
Proto se výsledek atomického dialogu porovná s owned DefaultPath ještě před
normalizací slashů a ParsePath. Jde o identitu hodnoty, nikoli sledování edit
událostí: i znovu napsaná přesně shodná hodnota je stejný implicitní cíl.
Jiný text, i pokud se později normalizuje na tentýž root, zůstává explicitní.
Prázdný záměrný vstup si ponechává původní explicitní controller sémantiku.

Nové private metody CFilesActionDiskTarget:

- HasDefaultText porovná i NUL v reálné caller kapacitě, nejvýše SAL_MAX_PATH.
- MatchesParsedDefault požaduje úplný původní text, PATH_TYPE_WINDOWS, existující
  directory interpretaci a secondPart přesně na univerzální masce. Pokud parser
  nalezl jen kratší existující prefix, odmítne ještě před SalSplitWindowsPath,
  který by jinak mohl nabídnout vytvoření chybějícího zbytku kořene.
- MatchesSplitDefault ověří bounded directory NUL, vlastnictví mask pointeru,
  kapacitu pro*.* a druhou NUL a přesný prefix captured rootu. Připouští pouze
  odebrání redundantního koncového separatoru, které provádí Windows splitter;
  drive root C:\ se nikdy nesmí změnit na relativní C:.

Před split už existuje recheck živého panelu po ParsePath; po split přibyl nový
recheck. Stávající recheck před script build/start zůstává. Selhání implicitního
preflightu nastaví IDCANCEL a použije lokalizovaný systémový ERROR_RETRY přes
SalMessageBox, bez nové hardcoded UI věty. Explicitní cíl si ponechává parser,
masky, confirmation a existující tvorbu adresářů; post-split panel recheck platí
i pro něj. Copy-to-selected-dirs zůstává mimo tuto jednu cílovou větev.

Porovnání je lexikální, stejně jako drop root kontrakt, nikoli obecná filesystem
canonicalization nebo reparse/alias bezpečnostní transakce. Není zárukou proti
změně filesystemu jiným procesem mezi kontrolou a workerem. Žádné obcházení
Windows bezpečnosti, změna registrů, SDK ABI, DropCopyMove ani odloženého ChangeDir.
Branch destination guard zůstává zapnutý; metody samy nejsou command admission.
