projektových registrací a 4 native testových souborů. Úzký donorový diff

Mapování: [REUSE.tsv](../REUSE.tsv), audit [BOUNDARIES.md](../BOUNDARIES.md).

CRenamerDialog::LoadSelection zachytí S05 CSalamanderDiskSelection před
spuštěním workeru; owned CSourceFile kopíruje přesné FullPathW a metadata.
Neúspěšný snapshot/allocation nespustí thread a neodhaduje root+basename.
V filename mode se cílový rodič odvozuje z každé položky; relative mode
zachovává společný root a full mode celý zadaný cíl. Preview, ruční režim,
BuildScript a operace používají stejnou identitu. Heap scratch má explicitní
kapacity 4*SAL_MAX_PATH; NameLen už není patnáctibitové pole. NewSourceFile
zachovává nothrow/low-memory větve i lokální obnovu CRT debug-new makra;
SetName nepoškodí starou identitu při alokačním selhání. Undo před I/O
rezervuje obnovený model a po úspěchu provede allocation-free SwapName;
Blocks je zkopírováno před zánikem undo entry.

RenamerIO vede enumeraci, atributy, mkdir, rename/move, copy a Undo přes wide
Win32 API s extended drive/UNC cestami. Zachovává trailing dot/space identity,
normalizuje jen dot/dot-dot a zachovává read-only retry/restore. Unicode
ordinal porovnání nealokuje uvnitř sort callbacků. Nezavádí se nové SDK,
CFileData layout, skener ani Branch UI. MENU_EVENT_DISK v renamer.cpp je
stejné jako před etapou; plugin nepodporoval archive/FS vstup a S07 mu
diskový snapshot do virtuálního režimu nevnucuje.

Adaptační kód: pouze dvě registrace již převzatých testů ve stávajícím
tools/run_native_tests.ps1. Ikonočtečka, Filecomp a všechny dosavadní testy
zachovány. Žádná donorová assertion odložena nebo oslabena. Attribution
je viditelné v doc/third_party.md; SPDX/copyright beze změny.
