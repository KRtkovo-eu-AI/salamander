## Provenance and scope

Pinned PR KRtkovo-eu-AI/salamander#769 donor:
47661e92d4b3cbe5bb593ae3d75a3f1f698ef413. Only BranchItemRenamed, its declaration,
and the three RenameFileInternalW success-hook groups are imported. Existing
S20a wide source/parent I/O and panel_temporary_selection.h are reused unchanged.

After a successful rename, update the per-row name, relative path, full-path
cache key, cache-to-row mapping, retained scan entries and pending focus, then
cancel/restart the scan. Stop the icon reader while changing row/cache metadata.
F2 and inline rename require a currently mapped Branch row. An owned full cache
identity is checked again after the modal F2 dialog before using the old pointer.
The metadata mutex is released before cancellation/refresh callbacks. These
integration guards adapt the donor to the staged target and avoid holding its
metadata lock across callbacks. No new SDK layout, vtable, allocation policy,
translation, public option, Windows registry or security-policy change.

Only CM_RENAMEFILE and the guarded direct rename paths are enabled. Copy/move/
delete, clipboard mutations, packing and unverified plugins remain disabled.
The experimental Branch activation remains off by default. Source paths identify
a selected filesystem object by name/path; this is not a filesystem transaction
and cannot prevent external replacement of that file.
