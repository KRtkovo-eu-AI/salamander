# S31b5b1 — přesný kontext resolveru a bezpečné chybové zprávy

## Rozsah

Uzavírá D02/D03 auditu S31b5a. CFilesWindow::ParsePath již nepoužívá 520-byte
scratch s ignorovaným GetGeneralPath FALSE. Diskový základ bere z GetPathW,
převádí do UTF8 s roundtrip kontrolou a ověřuje skutečnou kapacitu heap bufferu.
Archiv/plugin FS zachovává přes GetGeneralPath; neúspěch explicitně odmítne.
Společný SalParsePath zachovává rozlišení disk/archive/FS a error enum, hlídá
NUL v caller kapacitě, fallback pro prázdný vstup a doplnění archive lomítka.
Chybová zpráva vlastní cestu/detail/title před dalším LoadStr, změří formát a
alokuje přesnou kapacitu; bad_alloc má dosavadní lokalizované low-memory hlášení.
Vstupní diagnostické formátování je omezené pathBufSize, včetně NULL/zero vstupu.
Dosavadní GetRootPath/reconnect ABI nadále používá legacy root buffer; příliš
dlouhý UNC server/share nyní výslovně odmítne před I/O, místo zkráceného aliasu.
Nejde o novou deklaraci síťové podpory ani o plnou lexical-path normalizaci.

Žádná změna Windows registrů, Shell bezpečnosti, SDK ABI ani Branch guardů.
FilesAction dosud odmítá Branch target; DropCopyMove zůstává root-only.
Odložené ChangeDir ve starém worktree se nemění a nepoužívá k sestavení.
