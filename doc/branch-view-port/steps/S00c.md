# S00c — Diagnostika prvního spuštění s prázdným configem

Stav: PLANNED. S00b opravila evidenci a cleanup a prošla Debug/Release běžným
panelem, viewerem, kopií a normálním shutdownem. S01 nezačala.

S00a na původním targetu a S00b při opakování pozorovaly bílé plochy bez child
panelů při prvním startu s vlastním prázdným `config.reg`. Zdroj
`CConfigurationStorage::LoadRegFile` výslovně považuje nulovou délku za
clean/default config. Po normálním zavření, uložení a restartu jsou panely
vykreslené. Příčina zůstává neurčena; nelze bez důkazu označit za chybu Computer Use.

Nejmenší postup: znovu ověřit finální S00b na nové vlastní konfiguraci,
porovnat inicializaci panelů a config defaults s úspěšným restartem; určit,
zda jde o produkt, fixture nebo nástrojové pozorování. Případný potřebný malý
fix nejprve ohraničit v PLAN; žádný donorový import ani S01/S02.
Akceptace: Debug/Release GUI při prvním startu i restartu nad vlastním korpusem,
konkrétní doložená příčina a její řešení, relevantní build/native brána pro
případný kódový fix, aktualizace evidence. Piny SOURCE zachovat, bez push/PR.
