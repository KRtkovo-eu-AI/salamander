## Production scope and donor relationship

Existing pinned donor ZIP UnpackWholeArchive, MatchFilesToMask, ExtractFiles and
ExtractSingleFile permit SDK Skip with a successful return. A separate internal
WholeArchiveExtracted flag now qualifies archive deletion. It starts false in the
constructor and true on entry to actual whole extraction. Nonmatching central
entries, empty mask/no matches on a nonempty archive, an enumeration error followed
by extraction of a usable subset, unsafe-target Skip, unsuccessful per-entry output
and directory/parent creation Skip mark it false. A successful directory Retry
does not mark it incomplete. Valid genuinely empty ZIP retains prior behavior after
normal CheckZip. Existing ErrorID/UserBreak and sticky volume-list guards remain.

When delete is requested with incomplete extraction, the wrapper reports new
localized IDS_UNPACK_INCOMPLETE through the existing themed message service and
returns FALSE before sorting/handoff. The source archive is kept. No-delete SDK
Skip continues to return according to the existing behavior; produced partial
files remain. The archive-testing AllFilesOK flag is retained and now also marks
unsafe-target Skip false. No new path buffers/conversions, public SDK/vtable,
CFileData or host/Branch admission change. Mask-selected subset is deliberately
distinguished from the entire archive, even when extracting that subset succeeds.
Directory creation Skip can leave the legacy per-entry success flag true; the
separate sticky whole-completion flag prevents that from authorizing deletion.

The partial-enumeration audit also found an actual stale read: after rejected
ExtrFiles->Add deletes fileInfo and sets local errorID, the code checked member
ErrorID before reading fileInfo->Size. It now checks local errorID, avoiding the
read of released storage. This is a concrete failure-path fix, not a suppressed
allocation check. Existing allocation semantics, parser/decompressor/CRC and path
safety checks are preserved.7Zip and all shared/vendor sources remain unchanged.
