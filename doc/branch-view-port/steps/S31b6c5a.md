## Behavior and adaptation

Alt+F9/Unpack is admitted by the central Branch command gate. The existing
file-on-disk menu/toolbar enabler already accepts Branch files and is reused.
The controller retains the exact archive source and its physical parent,
not collection root plus basename. Existing live source/target/modal/backend
snapshots and pre/post-callback validations remain active.

The actually selected whole-archive backend must have a current configuration
and plugin binding and the bundled relative DLL identity zip\zip.spl. This
checks the selected backend, not the file extension or listing plugin. Other
plugin identities (including7Zip), custom DLLs and external unpackers are
refused before target creation in the controller. Dispatcher and concrete
wrapper independently require the exact source context, an ordinary live disk
target context, qualified backend and no archive deletion. The wrapper repeats
admission after InitDLL and before SDK operation context creation. Ordinary
callers and legacy NULL compatibility are retained. The DLL identity is a
staged host policy, not cryptographic authentication of arbitrary plugins.

For a Branch source, the existing Delete archive control is disabled/unchecked;
transfer ignores it even if a callback enables/checks it. Controller and both
backend layers independently refuse deletion. A successful collection operation
does not apply ordinary synthetic-root folder focus. Existing source/target
busy, scan/generation/retarget guards, scoped refresh/priority, notification and
implicit-root checks remain intact. Snapshots are not filesystem transactions.

The adaptation is needed to open only a verified operation in the staged port.
It reuses donor Unpack/dialog/backend code by Open Salamander Authors, Milan Kase
and Samandarin Contributors (GPL-2.0-or-later), plus the already qualified local
snapshot helpers. Public SDK/vtables, CFileData, bundled plugin/vendor source
and notices are unchanged. No new MAX_PATH path buffer or unlocalized product
string was added; errors reuse existing localized Windows messages.
