## Adapted donor and scope

Pinned donor CExtractCallbackImp, C7zClient::Decompress and bundled whole-archive
wrapper remove entries when GetStream begins, ignore callback errors in Decompress
and accept OPER_CONTINUE for archive-volume handoff. This adaptation separates
selection completion from ordinary SDK Skip. Existing directory/path guards,
CRC/data-error reporting, Keep/Delete/Cancel and output cleanup remain intact.
No vendor decoder, shared SDK/vtable, CFileData, host/controller or Branch
admission changes. No Windows security/privacy/registry changes.

Callback Init captures expected unique selected items. GetStream uses find instead
of inserting unknown indices, tracks one pending requested item, records missing
results and sticky overwrite Skip, resets per-item Skip, and counts a rejected
path append as an error. SetOperationResult counts only requested successful
extract-mode output (file or explicit directory); errors/Skip cannot count as
completion. IsSelectionComplete requires zero NumErrors, no sticky incomplete
flag, no pending result, empty requested map and exact successful item count.
Ancillary solid-stream decoding does not count as requested output. The existing
E_STOPEXTRACTION normalization in DoDecompress remains unchanged.

Decompress initializes an optional internal bool result to false before OpenArchive.
It qualifies whole completion only when all requested records form the complete
unique in-range archive index set (successful GetNumberOfItems), decoder result is
S_OK and callback reports complete selection. Partial mask, duplicate/out-of-range
indices, missing records and count-query failure cannot qualify deletion. The
existing CANCEL cleanup is preserved, callback allocation refusal now unwinds
through the existing catch to free fileIndex, and default FILETIME is initialized.
No existing allocation-error checks were removed. No new SDK method was added.
Noncancel incomplete output returns OPER_CONTINUE; no-delete whole/selected/preview
callers retain their existing != OPER_CANCEL policy. Whole wrapper requires both
OPER_OK and whole completion before checked single-volume Add, after ordinary
progress/client/directory cleanup. Incomplete delete requests use localized
IDS_UNPACK_INCOMPLETE via existing themed plugin Error service and return FALSE.

This is reported-output completeness, not atomic filesystem identity/transaction
or a new guarantee for ignored legacy metadata-write errors. Multi-volume 7Zip
source discovery is not qualified here and existing Branch deletion restrictions
remain. Dense Unicode ChangeDir remains frozen/deferred NOT_VERIFIED.
