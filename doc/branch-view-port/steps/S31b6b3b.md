## Implementace a hranice

Interní PackGetVerifiedBranchUnpacker kontroluje existující archive panel,
Contains přesně předaného private metadata interface, shodu požadovaného archivu
s GetZIPArchive, skutečného GetPluginDataForPluginIface ownera, SupportPanelView
a bundled DLLName zip\zip.spl (case insensitive). Lookup nespouští InitDLL.
Asociace ani pouhá přípona nepovolují Branch operaci; listing se nepředává
nově nastavenému cizímu pluginu/external handleru. DLL klasifikace vymezuje
ověřený interní rozsah, není kryptografickým ověřením původu binárky.

UnpackZIPArchive zachovává live-registry kontrolu před prvním target getterem
a directory snapshot TRUE. Branch target smí být existující diskový kořen,
copy ze ZIP listingu; source Branch, delete a jiné backendy zůstávají odmítnuté.
Owner binding se kontroluje před dialogem i v validateDiskTarget po callback
hranicích. Přepsání implicitního Branch cíle se odmítne před normalizací/ParsePath,
tedy dříve než neověřený virtuální cíl může vyvolat další callback. Ordinary
manual parsing zůstává zachované. Neplatný root vrací ERROR_RETRY, neregeneruje
náhradní adresář; po chybě se neodznačí zdrojový výběr.

PackUncompress před dispatch odmítne Branch bez directory-mode snapshotu,
neshodný/null output text nebo neplatný ZIP binding. CPluginData::UnpackArchive
po InitDLL, před vytvořením operation context a SDK callbackem, ověří target
a stejný binding navíc proti this. Záměna ownera za jinou ZIP instanci nestačí.
Všechny tři původní plugin dispatch větve a ordinary null/foreign/different
archive fallbacky zůstávají zachované. CFilesActionDiskTarget::IsCurrent,
původní atCopy/atMove resolver, delete body, CFileData a veřejné SDK beze změny.
Zdrojový listing lifetime je samostatná otevřená hranice, nikoli touto target
kontrolou vyřešená transakce nad zdrojem/filesystémem.
