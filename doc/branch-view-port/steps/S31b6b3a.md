## Skutečný dispatcher není lookup podle přípony

PackGetPluginForArchiveFile nejprve čte PackerFormatConfig a teprve při chybějící
asociaci zvažuje owner otevřeného panelu. Je to legitimní lookup pro jiné vstupy;
nelze jeho výsledek zaměnit za důkaz vlastníka již existujícího listingu a není
důvod měnit globálně jeho zavedenou sémantiku.

PackUncompress oproti tomu před asociací kontroluje ptZIPArchive, Contains přesně
předané private metadata interface a shodu GetZIPArchive s požadovaným archivem.
Pak použije GetPluginDataForPluginIface. Platný owner se nesmí nahradit jiným nebo
externím handlerem po změně konfigurace. Null/foreign metadata nebo jiný archiv
mají své původní ordinary dispatch případy. Budoucí Branch admission nesmí těmto
fallbackům dát oprávnění jen proto, že asociace ukazuje na ZIP.
GetPluginDataForPluginIface hledá existující plugin podle uloženého PluginIface;
nejde o příkaz k InitDLL. ZIP ListArchive vytváří CPluginDataInterface a položky
obsahují CZIPFileData; 7-Zip bere jinou vlastní CPluginDataInterface a CItemData.
Nepředávat tyto privátní položky jinému archiveru a neměnit CFileData.Name na cestu.

Host F5 příkaz již existuje a archive source má EnablerFilesCopy. Vlastní
UnpackZIPArchive má pořád přímý Branch guard; pouze nové menu/enabler změny by
nebyly implementací. Nutná kontrola před modalem/create a opět v samotném interním
PackUncompress dispatch, bez nového veřejného SDK. Post-InitDLL target identita
ze S31b6b2b1 a skutečné controller zapojení S31b6b2b2 musí zůstat zachované.

ZIP a7-Zip wrapper UnpackArchive,7-Zip Decompress/GetStream, association lookup a
external UnpackUniversal jsou po normalizaci EOL přesně shodné s donorem.

pointerem; controller již přijatou capacity/lifecycle adaptací. Přesné function
SHA256 a donor diffy jsou v externí evidenci. Neimportovat znovu celý backend.

## Doložená 7-Zip konverzní mezera

GetStream sestaví TargetFileName z TargetDir+NameInArchive a předá jej do
ProcessedFileInfo.FileName = GetUnicodeString(TargetFileName). Na Windows inline
GetUnicodeString(const char*) volá MultiByteToUnicodeString s CP_ACP defaultem;
Windows tělo používá MultiByteToWideChar(codePage,...). Pozdější stream Open navíc
roundtripuje GetUnicodeString(GetAnsiString(ProcessedFileInfo.FileName)).
Pouhá přítomnost GetSalamanderUnicodeString/GetSalamanderLongPath ve structs.h
neznamená jejich použití v této větvi. Otevírání archivu v7zclient.cpp přitom již
volá explicitní UTF8-first/long helper, což tuto jinou output větev neopravuje.
Vendor g_ForceToUTF8=true je pouze non-Windows implementace; nepoužít jej jako
vysvětlení správného Windows chování ani neřešit chybu globální změnou code page.

Izolovaný native probe překládá skutečné Windows MultiByteToUnicodeString2,
oba MultiByteToUnicodeString overloady, skutečný header GetUnicodeString a existující
GetSalamanderUnicodeString. AString/UString storage jsou explicitní std::string/
std::wstring facades; konverze provádí skutečné Win32 API, bez host/plugin facades.
Tři vstupy: ASCII, více Unicode komponent s emoji, úplná dlouhá Unicode cesta.
MSVC /W4 /WX Debug a Release:6 checks/config, skutečné ACP1250. ASCII zachováno;
legacy default převod změní obě Unicode identity, UTF8-first helper zachová všechny3.
To je pozitivní důkaz současné neshody, nikoli PASS správného rozbalování.
Nebyl otevřen/zapsán soubor ani spuštěn archiver. Neodvozuje se z toho přesný GUI
chybový kód nebo chování celé7za knihovny s dlouhou cestou. Budoucí oprava potřebuje
permanentní regresní test správného output stream kontraktu, vlastní I/O a GUI.

První konstrukce probe postrádala AString overload a kompilátor /WX ji zastavil
na rekurzi; doplněn skutečný chybějící overload před prvním spuštěním. Produkce se
neměnila, žádná rekurze se nespustila. Po rozdělení názvu command record a result
JSON je finální evidence jednoznačná. Do repozitáře se tento dočasný diagnostický
probe nepřidává; původní testy se nevypínají ani neoslabují.
