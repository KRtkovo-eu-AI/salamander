Lokální adaptace zachytí vlastněný source/root/cache key, generaci a ID zdrojového
i cílového tabu, typ/cestu cílového panelu. Po Load/Resolve/GetIDList/GetPath
callbacku nepoužije zrušený řádek a nezmění mezitím přepnutý panel. Zdroj se
čte přes IPersistFile::Load wide extended path, standardní IShellLinkW a původní
SLR_ANY_MATCH|SLR_UPDATE. S_FALSE z Resolve je tiché zrušení. COM/PIDL reference
se uvolní i na chybových cestách. Neplatný/inaccessible cíl použije existující
lokalizované IDS_SHORTCUT_WRONG_PATH; relativní/device cesty se nepředávají
jako diskové cíle. Neobnovuje se execution, association ani obcházení zabezpečení.

GetPath u skutečného dlouhého cíle v testu vrátil krátký DOS alias. Po úspěšném
standardním Resolve proto preferujeme filesystem PIDL přes SHGetPathFromIDListEx;
pokud PIDL není dostupný, zůstává GetPath fallback. Vlastní PIDL bez filesystem
cesty se bezpečně odmítá. GetLongPathNameW vrátí úplnou podobu Windows aliasu;
žádná vlastní tvorba aliasů ani fallback launch přes 8.3 se nepřidává. Existence
cíle se ověřuje wide GetFileAttributesW; reparse body přes CreateFileW metadata
handle a GetFinalPathNameByHandleW s close. Vše při běžných oprávněních Windows.
Navigace na soubor používá rodičovskou wide cestu a UTF8 focus a po úspěchu
skutečný wide basename; po neúspěchu/rescue se nesmí označit jiný stejnojmenný
soubor. Nové buffery jsou heap-backed, bez nových MAX_PATH path stack arrays.
