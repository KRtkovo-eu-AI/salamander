# S31b6a — audit archivního cílového resolveru

Auditovaná revize `36af45263509bc288e5f1ca319fab55466c7dd05`; donor
`47661e92d4b3cbe5bb593ae3d75a3f1f698ef413`, čistý referenční checkout.
Bez změny produkce/testů a bez aktivace dalších Branch operací. Výsledkem je
konkrétní implementační pořadí pro otevřené G04, nikoli runtime validace.

## Tři odlišné vstupy

| Vstup | Volání a aktuální kontrakt | Donor / chybějící část |
| --- | --- | --- |
| F5 z otevřeného archivu | mainwnd3 -> UnpackZIPArchive -> ParsePath -> PackUncompress -> listing-owner plugin; archivní relativní jména přes PanelSalEnumSelection | Donorová funkce se liší jen naším vstupním Branch guardem a chybějícím přiřazením data.SourcePanel. Samotné přiřazení v tomto callbacku není používáno a nepřináší podporu cíle. |
| Alt+F9 nad diskovým archivem | mainwnd3 -> Unpack -> PrepareUnpackArchiveSource -> CUnpackDialog -> ExecuteUnpacker | Již lokálně adaptováno v S31b4a/b/c1. Branch source i target stále odmítnuty. Úplná owned source identita vzniká před modalem; po něm se již nečte file->. Není to stejná cesta jako F5. |
| Alt+F5 sbalení | Pack -> PanelEnumDiskSelection, ExactFileSelection a IsVerifiedBranchPacker | Branch disk source má dřívější ověřené ZIP/7-Zip scénáře; Branch target stále odmítnutý. Packer whitelist nelze použít jako důkaz unpacker schopností. |

Při drag&drop z archivu WM_USER_DROPUNPACK ve fileswnb.cpp volá
UnpackZIPArchive(NULL, FALSE, tgtPath); explicitní cesta nemá target panel.
Není správné vnutit jí existenci protějšího panelu. DeleteFromZIPArchive také
používá tuto funkci s deleteOp=TRUE; změna copy větve nesmí měnit mazání.
Archive-to-archive a archive-to-FS mají samostatné temp/callback větve.

## Konkrétní nálezy

**A01 — krátké destination mezivrstvy v UnpackZIPArchive.** Hlavní path již má
SAL_MAX_PATH a CCopyMoveDialog dostává tuto kapacitu, ale explicitní tgtPath
se zkracuje přes lstrcpyn(..., MAX_PATH), ParsePath stále dostává MAX_PATH,
changesRoot a newDirs jsou MAX_PATH, textBuf je 2*MAX_PATH+200. Kopie prefixu
memcpy(changesRoot, path, secondPart-path) nemá lokální kontrolu kapacity.
Oprava samotného dialogu proto nestačí; zkrácený kontext může změnit operaci.
Dále legacy create/cleanup používají ACP-dependent větev a RemoveEmptyDirs.
Jde o staticky doložené mezery, nikoli nově provedený exploit nebo GUI pád.

**A02 — životnost archivního cíle.** Ani UnpackZIPArchive ani Unpack nevyužívají
CFilesActionDiskTarget z fileswn8.cpp. F5 cesta má po modalu i virtuální větve
s target-> přístupy; běžné zastavení refresh není důkaz zachování identity
cílového tabu. Diskový Copy/Move snapshot nelze mechanicky přesunout:
Capture přidává root\*.*, HasDefaultText a MatchesParsedDefault očekávají masku,
ale extrakce požaduje adresář bez operační masky. Potřeba owned root/tab/type/
generation a live-registry validace zůstává, klasifikace defaultu musí odpovídat
extrakci. Source listing/selection a reentrantní plugin callbacky mají vlastní
životnost; samotný target snapshot ji nedokazuje.

**A03 — přímé Unpack není hotové Branch rozbalení.** PrepareUnpackArchiveSource
již bere GetItemFullPathW a odmítá nevratné nebo příliš dlouhé UTF8 identity.
Ale controller zatím Branch source nepovoluje; sourceDirectory pochází
z GetPathW a branch-specific relativní cíle je nutné výslovně rozhodnout.
Následné mazání archive volumes, refresh a další callbacky vyžadují své důkazy.
Dlouhá source GUI cesta zůstává odložená kvůli ChangeDir; dlouhý target ji
nenahrazuje. Původní ChangeDir worktree se v této etapě neupravovalo.

**A04 — backend a vlastník listingu.** PackUncompress v pack1.cpp již před
konfigurovanou asociací respektuje GetPluginDataForPluginIface pro existující
listing. Tuto ochranu zachovat; nepředat soukromá listing data jinému pluginu
při změně konfigurace. ExecuteUnpacker v packers.cpp je samostatný dispatcher
pro whole-archive operaci. ZIP a 7-Zip i external/unknown backendy je nutné
ověřit v odpovídajícím vstupu, nikoli odvodit z IsVerifiedBranchPacker.

**A05 — donor není hotový resolverový předkrok.** UnpackZIPArchive v donoru má
stejné krátké buffers a resolver capacities. Není zde hotový donorový bezpečný
Branch target patch k přímému převzetí. Chybějící data.SourcePanel v této funkci
neovlivňuje PanelSalEnumSelection, jenž deleguje na _PanelSalEnumSelection;
nezaměňovat s PanelEnumDiskSelection pro diskové sbalení. Nové lokální opravy
jsou odůvodněné doloženou integrační mezerou a mají zůstat úzké.

## Důkazy a skutečný rozsah testů

Externí `evidence/S31b6a/Audit.py` prošel nad auditovaným HEAD: přesné extrakce
funkcí a donor diffs, normalizované SHA256, výše uvedené buffer/callsite
vazby, existující listing-owner dispatch a registrace pěti testů. Uloženo
v audit.json a {UnpackZIPArchive,Pack,Unpack}.diff; žádné logy v Gitu.

Existující branch_unpack_source_tests kompiluje skutečný source helper a
konverze s explicitním panel/item facade; skutečné soubory dokládají přesnou
identitu a owned capture, nikoli celý controller nebo decompressor.
unpack_dialog_path_tests používá skutečné Unicode HWND a Transfer s explicitním
scaffoldingem. unpack_cleanup_tests zkouší vlastní NTFS stromy a junctions;
branch_archive_selection_tests diskový packing callback a source cleanup.
zip_extract_target_tests pokrývá ZIP target guard a I/O helpery, nikoli všechny
pluginy. Registrace v tools/run_native_tests.ps1 ověřena, žádný z těchto native
programů nebyl v dokumentačním auditu nově spuštěn.

S31b4c1 již opravila starý ZIP MAX_PATH target limit a má vlastní ordinary
Debug/Release GUI long-target důkazy. Starší rejection ze S31b4b tedy není
aktuální překážkou tohoto ZIP scénáře. Z toho ale neplyne PASS pro F5 archive
panel -> Branch target, jiné backendy nebo long-source GUI. V tomto checkpointu
žádný nový native/build/GUI/CodeQL/clean full-suite běh.

## Nejmenší navazující podetapy a akceptace

1. **S31b6b1:** opravit pouze diskovou destination větev UnpackZIPArchive,
   zatím ponechat Branch guards. Owned heap buffers, skutečné kapacity,
   lossless explicitní tgtPath a default z wide identity, bezpečné vytvoření,
   cleanup a notification prefix; žádné zkrácení. Relevantní native v D/R,
   host D/R a skutečné ordinary archive-panel F5 ASCII/Unicode/byte-long/
   UTF16-long target, Cancel a neúspěch s kontrolou vlastních dat. Zachovat
   archive delete a virtuální větve; případnou sdílenou závislost nejprve zúžit.
2. **S31b6b2:** owned diskový target lifecycle pro tuto extrakci s adresářovým
   defaultem, validace před vytvářením i backend callbacky; native stale/closed/
   generation a GUI modal switch/closed/detached v D/R. Znovupoužít interní
   lifecycle princip, nevytvářet nové veřejné SDK ani měnit Copy/Move masky.
3. **S31b6b3:** až potom selektivní Branch destination admission pro skutečně
   ověřený listing-owner backend. F5 vybrané položky s duplicitními basenames,
   podadresáři, přesným výstupem/sentinels; neznámé/externí/FS případy zachovat
   odmítnuté do jejich vlastního ověření. ZIP ani 7-Zip nejsou předem PASS.
4. **S31b6c:** přímé Unpack diskového archivu rozdělit na source admission,
   target lifecycle/admission a následné delete-volume chování; přesné dílčí
   testy zapsat před implementací. Pack Branch target je další samostatná
   větev, nikoli součást automatického odemknutí při rozbalování.

Toto je uzavřený audit; implementace začíná až S31b6b1. G04/G05 i celá S31
zůstávají otevřené, S32 se nezahajuje, bez push/PR. Windows security/registry,
SDK ABI, CFileData basename smlouva a donor pin beze změny.
