## Změna

Stávající donorové/target CompressFile, UncompressFile, MyEncryptFile a
MyDecryptFile měly pouze narrow fileName i při volání z DoChangeAttrs, který
již vlastní exactName. Nový optional const wchar_t* zachová přesnou identitu;
legacy interní call sites dál fungují s default NULL přes UTF8-first/ACP
WorkerOperationPathW. Čtyři volání v DoChangeAttrs předají owned wide vstup.
Nejde o SDK/vtable ani exported plugin interface.

Pomocníci nově kontrolují dočasné odstranění Read-only/System, nepokračují
po jeho selhání, hlásí neúspěšnou obnovu atributů a zachovávají prioritu původní
chyby. EFS preserveDate flow nepoužije FILETIME po failed GetFileTime; neprovede
pak Encrypt/Decrypt API. Kontroluje i SetFileTime a otevření handle k obnově.
Handle close i restore zachované; původní chyba se nepřepíše cleanupem.
SYSTEM confirmation/cancel/all policy zůstává. Žádné registry/security policy
změny, alias či přesměrování na jiný soubor. Nové path buffers pouze std::wstring.

## Diagnostická historie a limity

První rozšíření EFS matice mělo chybně ponechanou testovací odpověď All i pro
obecný chybový dialog. Při trailing-dot odmítnutí se test dostal do smyčky a
vlastní38s subprocess deadline jej ukončil. Odpověď změněna na platné Cancel,
stdout unbuffered; jeden opuštěný temp root byl explicitně ověřen jako vlastní
fixture a odstraněn s extended prefixem. Následně opraven cleanup SYSTEM test
před skutečnou EFS maticí. Tyto běhy jsou historické, nikoli důkaz PASS či obecné
nepodpory long EFS. Finální raw API reference odlišuje konkrétní trailing-dot
omezení od podpory dlouhých/Unicode cest. Bez prodlužování časových limitů a
bez odstranění kontrol. Native cleanup se týká jen vlastní fixture; ne SDK dat.
