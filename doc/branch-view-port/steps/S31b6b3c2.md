## Implementace

SevenZipExtractTargetError je lokální adaptace již ověřeného ZIP guardu. Odmítne
null/oversized target/entry a kombinované byte kapacity před _tcscpy. Kontroluje
relativní komponenty před extended prefixem: dot/parent/absolute, ADS, neplatné
znaky, trailing dot/space a Win32 devices včetně superscript variant. Testy těchto
odmítnutí probíhají v paměti, žádné škodlivé archivy/bezpečnostní dialogy. Zůstává
požadavek absolutního output rootu a podporované wide délky, bez ořezání.

GetStream převádí celou sestavenou cestu UTF8-first přes existující lokální
GetSalamanderUnicodeString. COutFileStream::Open dostává stejnou wide identitu
s GetSalamanderLongPath, žádný ACP roundtrip. Atributy používají SetFileAttributesW.
TargetFileName zůstává plná byte cesta pro host SafeFileCreate/overwrite UI a
chybové texty; parentPath má oddělené std::string úložiště. Obě directory creation
větve kontrolují návrat CheckAndCreateDirectory, selhání abortuje operaci.
Nová bad_alloc větev v GetStream zachová opuštění critical section a OOM výsledek.

Původní char SafeDeleteFile deleguje do interního SafeDeleteFileW přes stejný
UTF8-first vstup jako dříve. Wide overload zachovává původní DeleteFileW a celý
DialogError Retry/Skip/SkipAll/Cancel loop; liší se jen odděleným wide I/O path
a byte displayName. Žádná nová SDK virtual metoda nebo změna staré signatury.
Extraction Cleanup/OnDataError používají přímo uloženou wide identitu. Readonly
odmítnutí a Windows oprávnění se neobcházejí, flagy se plošně nesnižují.

OutputCreated označuje pouze právě vytvořený/overwrite-schválený output.
Constructor/Init/InitTest jej resetují; GetStream jej spolu s OutFileStreamSpec
resetuje pro novou položku. SafeFileCreate zůstává před streamem, včetně Skip a
Cancel. Ownership vzniká až po jejich vyloučení; WholeFile=FALSE už v tomto bodě
umožní úklid při parent failure ještě před PrepareOperation. Cleanup zavře stream
před mazáním, vztahuje se jen na vlastní nehotový soubor (nikoli directory),
po rozhodnutí DataError se ownership uvolní. Skipped či předchozí dokončený
soubor nesmí být náhodně smazán. CRC/password/overwrite rozhodovací větve nebyly
nahrazeny novým přímým CreateFile, globální vendor code page sémantika se nemění.
