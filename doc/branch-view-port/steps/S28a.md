## Ovládání a hranice

Volba je v Options > Configuration > Panels (Panely):
„Use relative paths in the Branch View Path column“; česky
„Ve sloupci Cesta v pohledu na větev používat relativní cesty“.
Nezaškrtnuto znamená absolutní cesty a je výchozí stav. Zaškrtnuto znamená
adresář relativní vůči neměnnému kořeni zapnutí Branch View. Soubor přímo
v kořeni má Path tečku (.). Preference je společná pro oba panely.

Ukládá se jako „Branch View Relative Paths“ přes běžné ukládání konfigurace;
respektuje tedy také nastavení ukládání při ukončení. Zrušení dialogu nemění
hodnotu. Chybějící hodnota znamená FALSE, načtená hodnota se normalizuje.
Starší jazykový modul bez nového volitelného ovládacího prvku ji nepřepíše.
Zdrojové resources a všech 11 SLT překladů mají nový checkbox; skutečné GUI
bylo ověřeno s anglickým modulem, nikoli se všemi překlady.

DisplayDirectory a soukromý GetBranchViewDisplayDirectoryW odvozují zobrazovaný
adresář z již vlastněných metadat pod ItemsMutex. Pouze dva vstupy kreslení
sloupce Path používají tento accessor. GetItemDirectoryW, GetItemFullPathW,
GetItemIdentityW, GetItemRelativePathW a CompareEntryPaths jsou identické se
základem. TransferPanelPath pro vlastnosti/plugin callbacks používá dál úplný
adresář. Tooltip, identita, cache a vstupy operací zůstávají úplné.

CM_CONFIGURATION je úzce povolen v experimentální kolekci. Existující
BeginStopRefresh/EndStopRefresh a běžná aplikace konfigurace zůstávají zachovány.
Změna preference navíc explicitně překreslí oba panely (automatický Branch
refresh je stále odložen do S30). Nevzniká nový scan ani formát tab/history S29.
SDK, SOURCE.json, donor, workflow, heap diagnostika a bezpečnostní kontroly
zůstávají beze změn. Experiment je nadále výchozí vypnutý; LongPathsEnabled=0.
