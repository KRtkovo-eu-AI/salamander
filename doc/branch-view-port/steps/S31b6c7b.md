Internal unpackvolumes.h adapts the audited host volume loop without SDK changes.
The controller now builds a complete owned list before first attribute/delete I/O.
Text/Length/Allocated, bounded terminators, empty entries, per-path byte capacity,
absolute disk/UNC shape, path aliases/ADS and exact selected-source membership
are validated. Exact duplicate spellings are removed; case-distinct names remain
separate for Windows case-sensitive directories. Conventional extended drive/UNC
prefixes are accepted and Win32-long I/O gets an extended prefix. This is owned
path text, not handle-bound atomic filesystem identity or a filesystem transaction.

Qualified current bundled ZIP/7Zip decode UTF8 first and ACP only for invalid
UTF8, matching their existing read helpers; conversion must roundtrip exactly.
Unknown ordinary legacy producers use lossless ACP, never a guessed UTF8 path.
If the returned nonempty list does not include the exact selected source after
that single decoding decision, the entire list is refused before I/O. This may
refuse a Unicode UTF8-aware third-party backend pending explicit qualification;
ASCII and unambiguous ACP additional volumes remain compatible. An empty legacy
result is still a no-op; producer completeness/Add acknowledgement belongs to c7c.
Volumes may be on different absolute disk paths, as ZIP disk-change selection can
use other directories. Source membership is not proof those other files are valid
volumes; the trusted producer contract and c7c qualification remain required.

DeleteUnpackArchiveVolumeW uses GetFileAttributesW, clears only READONLY through
SetFileAttributesW, and uses DeleteFileW. Missing-file behavior and existing error
Retry/Skip/Skip All/Cancel remain. Unknown/unreadable attributes now fail explicitly
rather than guessing ARCHIVE attributes. A directory is refused. Current source/
target/backend context is checked on every iteration and after error dialogs;
owned paths survive producer-buffer mutation. Branch archive deletion stays
independently refused by controller/dispatcher/post-init wrapper.
